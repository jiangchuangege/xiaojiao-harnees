## 1. 摘要

`xiaojiao_install` 解决的问题是：让 N.E.K.O. 客户端内的助手帮助用户完成小焦的安装与上手，包括读取小焦后端的真实环境体检结果，以及给出分步安装指引。

它只做两件事：读小焦的体检接口并转述，以及输出固定的安装步骤。它不下载任何东西，也不改写任何配置。

---

## 2. 模块定位

本插件是 N.E.K.O. 猫娘与小焦之间的单向桥：用户在宿主里点「装小焦」，宿主加载本插件，插件再去读小焦后端的体检结果。

方向是单向的：插件只读小焦的接口，不向小焦写入任何内容。反向的偏好导入由仓库根的 `../../learn_from_neko.py` 单独完成，不属于本插件。

## 4. 安装与加载

### 4.1 安装位置

把整个 `xiaojiao_install/` 文件夹复制到宿主的第三方插件目录：

```text
%LOCALAPPDATA%\N.E.K.O\plugins\xiaojiao_install\
```

本机核对：`%LOCALAPPDATA%\N.E.K.O\plugins\` 目录存在，其下已有 `xiaojiao_install/`，内含 `plugin.toml`、`__init__.py`，以及宿主生成的 `config/plugin.toml`。

需要注意：本机已安装副本的 `plugin.toml` 与 `__init__.py` 都和仓库内这份的哈希不同，安装时间为 2026-09-08。升级时应以仓库内这份为准，覆盖后重启宿主。

### 4.2 不要放进内置插件区

宿主的应用安装目录下另有一处只读的内置插件区，形如：

```text
<N.E.K.O. 安装目录>\resources\bin\plugin\plugins\
```

放进去会出现「加载失败（入口点: 0）」。既有经验记录如此，本次核对未复现该现象，也未在本机看到该目录（本机的 `%LOCALAPPDATA%\N.E.K.O\resources` 不存在）。无论如何，插件都应放在 4.1 的第三方插件目录。

### 4.3 加载

复制完成后重启宿主。宿主会在启动时扫描第三方插件目录，按 `plugin.entry` 导入模块并实例化 `XiaojiaoInstallPlugin`，构造时会写一行日志「装小焦指引插件已加载」。

重启后，两个入口会出现在宿主中，名称分别为「装小焦·环境体检」与「装小焦·安装指引」。

### 4.4 确认已加载

在本仓库里无法验证宿主是否加载成功——宿主是独立程序。可用的确认方式是看宿主的插件列表与日志里是否出现上述加载提示。

## 5. 与主程序的交互

本节回答「它和小焦怎么交互、动的是哪个文件、哪个接口」。

本插件与本仓库的全部交互只有一次 HTTP 请求。

| 项 | 值 |
| --- | --- |
| 请求方法 | `GET` |
| 请求路径 | `/api/env` |
| 默认地址 | `http://127.0.0.1:5000` |
| 覆盖方式 | 环境变量 `XIAOJIAO_XIAOJIAO_BASE` |
| 超时 | 6 秒 |
| 被请求方 | `../../xiaojiao_app.py` 第 8335 行的 `api_env()` |
| 读取字段 | 响应里的 `items`，必须是数组 |

`items` 中每一项的字段：

| 字段 | 含义 |
| --- | --- |
| `name` | 检查项名称 |
| `ok` | 是否通过 |
| `need` | 缺失时的补救做法 |
| `info` | 该项的现状描述 |
| `dl` | 该项相关的下载地址，可为空字符串 |

本机实测的一条真实响应片段：`{"dl":"","info":"v3.13.13","name":"Python","need":"已装","ok":true}`。

小焦侧的体检是协议级检测，不是只看文件在不在：本地大脑按端口连通性判断，云端大脑会实际请求一次模型列表接口，通了才算通过。插件只是原样读取并转述，不做二次判断。

失败处理：请求超时、连接被拒或返回体里没有 `items` 数组时，`_fetch_env()` 返回 `None`，并往标准输出打印一行「读小焦 /api/env 失败(小焦后端没起?)」。

插件不读写小焦的任何文件，也不调用小焦的其他接口。

## 6. 两个入口的行为

两个入口都不接受输入参数，输入结构声明为空对象。

### 6.1 env_check（装小焦·环境体检）

先调用 `_fetch_env()`。

拉不到时返回：

```json
{
  "ok": false,
  "msg": "小焦后端(5000)暂未响应。要我先按『装小焦指引』讲讲安装步骤吗？",
  "install_steps": ["…"]
}
```

拉到时按 `ok` 字段把检查项分成已装与缺失两组，并为每个缺失项附上补救做法，返回：

```json
{
  "ok": true,
  "installed": ["已通过的项目名"],
  "missing": ["缺失的项目名"],
  "missing_how_to_fix": ["缺失项 → 怎么补"],
  "summary": "已装: …\n还缺这些(小焦帮你查了怎么补):\n…"
}
```

无论哪种情况，插件都会把完整结果写进日志：已装项、缺失项，以及每个缺失项的补救做法各占一行。这样即使返回文本被截断，从日志里仍能看到完整清单。

### 6.2 install_guide（装小焦·安装指引）

不需要小焦后端在线，直接输出固定的五步：

| 步骤 | 内容 |
| --- | --- |
| 1. 装依赖 | 到小焦项目目录运行 `pip install -r requirements.txt` |
| 2. 摆好大脑 | 小焦的 `/v1` 兼容 OpenAI 协议，模型不写死：放任意 GGUF 到 `C:/llama` 或项目目录走本地离线，或者配置任意 OpenAI 兼容 API 的地址、密钥与模型名。两者任一即可 |
| 3. 一键启动 | 运行 `python start_xiaojiao.py`，它会自动拉起多大脑（llama-swap 9292）、网页（5000）与已安装的 N.E.K.O. 客户端（48911 / 48912） |
| 4. 打开使用 | 浏览器访问 `http://127.0.0.1:5000`；页面内有视频、播客、音乐与 N.E.K.O. 四个入口 |
| 5. 体检 | 向助手说「装小焦体检」，即可调用环境体检看缺什么、缺项会影响哪个功能 |

返回结构为 `{"steps": [[步骤名, 说明], …], "guide": "可直接阅读的整段文本"}`。

## 7. 依赖与前置条件

| 依赖 | 说明 |
| --- | --- |
| N.E.K.O. 桌面客户端 | 必需。宿主提供 `plugin.sdk.plugin` 模块，插件的全部基类与装饰器都来自它 |
| 宿主 SDK 版本 | 需落在 `>=0.1.0,<0.3.0` 区间内 |
| Python 标准库 | 插件只用 `json`、`os`、`urllib.request` 与 `typing`，无第三方依赖 |
| 小焦后端 | 只有环境体检需要。`install_guide` 在后端未启动时同样可用 |

重要限制：本仓库内**无法运行**本插件。它依赖的 `plugin.sdk.plugin` 由宿主提供，仓库里没有这个包，因此既不能直接 `python __init__.py`，也不能在仓库内写单元测试。仓库内能做的核对只有静态检查（字段是否齐全、入口类是否存在、接口路径是否与后端一致）。

## 8. 边界与限制

### 8.1 只读

插件不修改小焦的任何配置或文件。体检发现缺失项时只给出文字说明，不会自动安装。

### 8.2 只覆盖安装与体检

插件不参与小焦的日常对话、工具调用或模型管理。这些能力在小焦自己的 Web 界面里。

### 8.3 地址固定为本机

默认地址是 `127.0.0.1:5000`，即小焦与宿主在同一台机器上。跨机部署需要自行设置 `XIAOJIAO_XIAOJIAO_BASE`。

### 8.4 安装指引是固定文本

`install_guide` 输出的是写死在代码里的五步，不会随仓库版本自动更新。若安装流程变化，需要同步改 `__init__.py` 里的步骤表。

### 8.5 依赖宿主日志查看完整结果

返回给宿主的文本对每个缺失项的说明截断到 80 字，补救做法截断到 60 字。完整内容只在日志里。这是为避免过长文本影响宿主展示，代价是需要看日志才能拿到全文。

### 8.6 未实测的部分

本次核对没有启动宿主，因此以下内容未实际触发：插件在宿主中的加载过程、两个入口的实际展示效果、后端未启动时的提示文案在宿主里的呈现。

## 9. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 宿主插件列表里看不到本插件 | 目录放错或宿主未重启 | 确认位于 `%LOCALAPPDATA%\N.E.K.O\plugins\xiaojiao_install\`，然后重启宿主 |
| 报「加载失败（入口点: 0）」 | 放进了只读的内置插件区 | 移到第三方插件目录，见 [4.2](#42-不要放进内置插件区) |
| 目录名被改过 | `plugin.entry` 里的模块路径与目录名必须一致 | 目录名保持 `xiaojiao_install` |
| 体检总提示后端未响应 | 小焦 Web 未启动，或不在 5000 端口 | 先启动小焦，或用 `XIAOJIAO_XIAOJIAO_BASE` 指向实际地址 |
| 体检结果与实际不符 | 结果来自小焦的实时检测 | 直接访问 `http://127.0.0.1:5000/api/env` 对照；不一致说明小焦侧探测有问题 |
| 缺失项的说明被截断 | 返回文本有长度上限 | 到宿主日志里看同一项的完整内容 |
