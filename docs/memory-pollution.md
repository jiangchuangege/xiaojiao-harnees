# 记忆污染：它把「工具给的」说成了「你说过的」

> 相关代码：`core/mem_filter.py`（写入侧）、`core/retriever.py`（注入侧）、
> `core/memory_vec.py`（时间线）、`xiaojiao_app.py`（检索闸门）
> 清理工具：`tools/clean_memory_pollution.py`
> 自测：`tools/test_mem_filter.py`、`tools/test_mem_source.py`、
> `tools/test_search_modifier.py`、`tools/test_timeline_search.py`

---

## 1. 症状

用户问：「你还记得上一次吗」

它答：

> 🧠 记忆检索中……
> 我记不起上一次我们聊了什么。
> —— 不过，我确实记得一些**你曾经提到过的内容**：
> 1. 你曾经问过"你还记得上一次吗"，我也这样回答
> …（后面跟着「哔哩哔哩」之类的内容）

问题不在"记不起"。问题在**那句"你曾经提到过的"**。

那些东西**根本不是用户说的** —— 是某一次抓取网页的结果被存进了记忆，
检索时又被贴上了"用户曾说过"的标签。

**这一条比"检索不准"严重得多**：检索不准是没找到；这个是把来源说错了。
前者用户会觉得"它忘了"，后者用户会觉得"它在编我"。

---

## 2. 根因（三处，缺一不可）

| # | 位置 | 错在哪 |
|---|---|---|
| 一 | 写入侧 `_remember_turn()` | 模型的回答里**带着工具渲染出来的原文**（`🌐 **URL** · HTTP 200 <正文>`），整段被存进记忆 |
| 二 | 注入侧 `retriever.retrieve()` | **只要正文不是「用户：…」的形状，就一律贴"用户曾说过"** —— 等于把「它说的」「工具给的」「它学到的」统统说成了「用户说的」 |
| 三 | 存量数据 | 库里已经躺着 253 条这类东西，光修代码不会让它们消失 |

第三处是关键：**只堵源头不清理，老污染照样会被检索出来。**

---

## 3. 修一 + 修二：写入侧过滤（堵源头）

`core/mem_filter.py`。两条硬规则：

- **规则 1** · 工具原始返回**绝不进**对话记忆；
- **规则 2** · 坏回复（占位符／未闭合／半截／空）**绝不进**记忆。

### 为什么不是"发现工具痕迹就整条不存"

实测那一轮对话里，**工具原文**和**它自己说的话**是**粘在同一行**的：

```
🌐 **https://httpbin.org/json** · HTTP 200 {"slideshow": {...}} 📖 **小焦解读** 这是一个返回 JSON 数据的网页…
```

整条丢掉 = 把它自己的那句解读也丢了。所以分两步：

1. **剥掉工具渲染段**（`🌐` 到 `📖` 之间的原始正文、抓取守卫提示、结果表）；
2. 剥完**还剩真内容**就存，**只剩空壳**就整轮不存。

实测在真实库的 253 条污染上验证：**210 条整轮不存**，
**43 条剥成只剩它自己的解读后正常存入**（这正是设计意图 —— 工具原文一字不留，它自己的话留下）。

### 三条踩过的坑（都写进了代码注释）

- **不能用裸的 `HTTP\s*\d{3}`**：实测误报 —— 有一条正常回答在**解释**
  "HTTP 200 表示请求成功，服务器正常响应"，删它就是删用户的知识。
  现在只认**工具渲染出来的那个形状**（`🌐 **URL**` / 带 URL 的抓取头）。
- **不能用"行里有竖线就当表格删掉"**：模型经常用 Markdown 表格回答，
  那条判据会把**它自己写的表格**一起吃掉。抓取结果的表只有一种
  （`📋 **页面结构速览**` 之后那块），所以只删那一块。
- **不能把"starts with ⏳"一律当坏回复**：实测有 18 条是
  "⏳ 等待提示 + 真正文"粘在同一条消息里，整行删会把真内容删掉。
  现在只剥**"⏳ 起、不超过 40 字、且不含句末标点"的那一小句**。

### 顺带修掉的一处："自己截出来的半截"

存记忆时回答截到 200 字，原来是直接 `[:200]` —— 实测把一条回答切在 URL 中间
（`…可直接在浏览器地址栏输入 \`https://htt`），存进去就是一条**半截**记录。
规则 2 说"半截绝不进记忆"，那**自己截出来的半截**当然也算。
现在走 `mem_filter.clip()`：切在句末。

## 4. 修三：注入必须标明来源

注入文本的每一行现在都带来源标记：

| 标记 | 含义 |
|---|---|
| `【你说过的】` | **用户本人**过去亲口说的话 |
| `【小焦说过的】` | **它自己**以前说过的话 |
| `【它自己记下的一条】` | 它学到的知识或工具结论 |

实际注入的样子：

```
- 【你说过的】我住在济南 ｜ 【小焦说过的】好的，济南记下了。
- 【小焦说过的】我以前说过我喜欢下雨天。
- 【它自己记下的一条】【知识】泉城是济南的别称。
```

**标不出"用户说的"，就不许说是用户说的。** 这是这一条的全部要点。

判定还要跟踪"当前说话人"：一段话可能折成多行，没带前缀的**续行算上一个说话人的**；
而**从头到尾都没有说话人前缀的**（学到的知识、工具结论）**一个都不算"你说的"**。
（实测把 `【http】HTTP 是一个协议…` 这种知识行当成了"小焦说的" ——
那同样是把来源标错，只是方向反过来。）

对应的系统提示词也改了：明确列出三种标记的差别，并写明
**"也不许把「小焦说过的」「自己记下的」说成「你说过的」"**。

## 5. 修四：修饰词不许当检索词

**症状**：模型会把「动态」「永久」这类**修饰词**当成检索词丢给 `web_search`，
搜回来跟用户想问的毫无关系 —— 跟当初拿「用」「索」去搜是同一个病。

**判据**：提取出来的关键词**只剩一个修饰词** → 不搜，反问用户要搜什么。

修饰词表：`动态 / 静态 / 永久 / 临时 / 长期 / 短期 / 可以 / 能不能 / 是否 / 关于`

> ⚠️ **这张表只用于"只剩修饰词"这个判据，一个字都不从关键词里删。**
> 因为修饰词在很多真请求里就是**内容本身**：
> 「汇总今天的科技动态」的检索词就是「今日科技动态」—— 把「动态」删了就错了。

实测：

| 输入 | 结果 |
|---|---|
| `动态` / `永久` / `可以` / `能不能` / `是否` / `关于` | **拒绝搜索**，反问用户 |
| `汇总今天的科技动态` | 照常搜「今日科技动态」 |
| `永久 存储方案` | 照常搜（有实义内容） |

## 6. 修五：时间性问题走时间线检索

**症状**：用户问「你还记得上一次吗」时，语义检索是按"像不像"找的 ——
而"上一次"这句话本身跟任何一段历史都不像，于是捞回来的是一堆**别的**记忆，
再被贴上"你提到过"，就答出了「哔哩哔哩」那种驴唇不对马嘴的东西。

**判据**：问法里出现 `上一次 / 上次 / 刚才 / 刚刚 / 之前 / 昨天 / 接着上次 / 前面`
→ **不走语义检索**，改走**时间线检索**：按时间倒序取最近 N 轮对话（含会话边界）。

非时间性问题**一个字都不动**，照旧走语义检索。

实测注入的样子：

```
（以下是**按时间顺序**排的最近 3 轮对话，越靠下越新；这一条走的是**时间线**，
不是相似度检索。）
- 【你说过的】第一轮我说我喜欢猫 ｜ 【小焦说过的】记住了，你喜欢猫。
- 【你说过的】第二轮我说我住在济南 ｜ 【小焦说过的】好，济南。
- 【你说过的】第三轮我说我在写代码 ｜ 【小焦说过的】在写什么？
```

它给的是一段**连续的**对话，而不是几条孤立的相似片段 ——
"上一次我们聊到哪了"这种问题，要的正是连续性。只取对话类（`dialogue` / `tool`），
不含 `fact` 知识条目：那些是联网学到的知识，不是"我们上一次聊了什么"。

## 7. 清污染（存量）

按规格顺序做：**先备份 → 扫 → 逐条列 → 清 → 报数**。

| 项 | 数 |
|---|---|
| 原条数 | **2573** |
| 清除 | **253** |
| 剩余 | **2320** |
| 备份 | `logs/backup_before_pollution_clean/<时间戳>/xiaojiao_memory_vec.jsonl` |
| 逐条清单 | 同目录下的 removed_list.txt（含时间与完整正文；是运行态产物，不进版本库） |

清掉的分类：

| 类别 | 条数 |
|---|---|
| 抓取结果头（`URL · HTTP 200`） | 194 |
| 载体抓取失败提示（`⚠️ 抓取失败`） | 52 |
| 载体抓取成功提示 | 2 |
| 坏回复（`<think>` 残留 / `【系统指令】`泄漏 / 整条占位符 / `（已回答）` / `你曾经提到过`） | 5 |

写盘用**临时文件 + 原子替换**，写到一半崩了不会留半个库。

### 没清的两类（如实）

- **"极短（< 8 字）"这一类实际清掉 0 条。** 命中的 5 条经逐条查看判定为
  **真实用户事实**（「我住在济南」「我喜欢吃辣的」…）—— 中文短 ≠ 垃圾，**保留**。
- **只列不清的 19 条**：18 条是**带 `⏳` 前缀但正文有真内容**（占位符粘在真回答前面），
  是污染，但删了会丢真内容；另有 1 条回答里带"系统显示失败"的自述。

## 8. 实测验收

| # | 验收项 | 结果 |
|---|---|---|
| 1 | 触发搜索 → 工具返回原文**不进** memory_vec | ✅ 那一轮新增 1 条记忆，是它自己的解读（`这是一个用于文档示例的占位域名页面…`），工具渲染头一字符都没进 |
| 2 | 回复是 `⏳__pending__` → 不进 memory_vec | ✅ 新增 0 条 |
| 3 | 检索注入 → 标明来源 | ✅ 注入文本带 `【你说过的】`/`【小焦说过的】`；旧的「用户曾说过」已不存在 |
| 4 | 「记忆机制改成动态能永久吗」→ 不拿「动态」去搜 | ✅ 日志实证：`检索词只剩修饰词，已拒绝搜索（原文='动态'，清洗后='动态'）` |
| 5 | 「你还记得上一次吗」→ 走时间线检索 | ✅ 日志出现「时间线检索」，注入的是按时间排的连续几轮 |
| 6 | 不再说「你提到过哔哩哔哩」 | ✅ 回答里既没有「你提到过」也没有「哔哩哔哩」 |
| 7 | 全量回归 | 见 `CHANGELOG.md` |

## 9. 如实标注（没做到的）

1. **写入侧过滤只堵了"对话记忆"这一条路。** `core/autonomy/learner.py`、
   `core/world/explorer.py`、`core/memory_deep.py` 也会往同一个库里写
   （`kind=fact`，即联网学到的知识）。那些是**有意写入的知识**，不走这次的过滤器。
2. **实测 253 条里，有 1 条剥完后仍残留一个被截断的 URL** —— 那是它自己解读里
   提到的地址（不是工具原始返回），但确实带着工具痕迹。1/253，如实记。
3. **修五的判据里「前面」天生有歧义**：「前面提到的那个函数怎么改」会被判成时间问题。
   自测 `tools/test_timeline_search.py` 的【E】组**故意把这条已知缺陷钉住**，
   免得以后没人数它。误触发时时间线仍会返回最近的真实对话，属可接受的降级。
4. **清库治标、过滤治本，但两者都只对"以后"有效**：
   已经进入对话上下文的错误说法没法追回。
5. **`⏳__pending__` 这一类在真实库里一条都没找到**（规格预期的这一类实测为空），
   如实记；真正命中占位符的是 `⏳ 正在调用工具：net_ip` 与 `（已回答）` 两种。
6. **新发现一类规格里没有的污染：完全重复的正文** —— 实测 **196 组、涉及 735 行**，
   其中**可无损去重掉 539 行**（最极端的一条抓取幻觉回复存了 **109 遍**）。
   去重本身无损，但清理工具**不自动做**，只统计打印，交给人决定。**目前没去重。**
