## 1. 项目定位

小焦是一套**载体优先架构**的本地 AI 助手。

它把大模型当作**可替换的火种**，把能力放在**载体**里。同一套载体接 4B、70B、360B 或未来任何模型，
用户看到的都是同一个助手：同一份记忆、同一套工具、同一个性格、同一套安全边界。

模型负责"当前这一小块"的生成；拆解、组装、调度、校验、记忆、编排由载体完成。
因此**换模型不需要改任何配置，也不丢任何数据**。

## 3. 与云端大模型的结构性差异

这里写的是**架构差异**，不是"谁更好"。两者解决的问题不同。

| 维度 | 本地小模型 + 载体（本项目） | 云端大模型裸用 |
| --- | --- | --- |
| 单次推理能力 | 受模型规模限制，4B 就是 4B | 取决于模型规模 |
| 多轮尝试 | 可循环多次、校验、择优（受用户可接受等待时间约束） | 一次前向对应一个答案 |
| 记忆 | 本地向量库，长期保存，可检索、可降级、不删除 | 由服务方决定，通常不长期保存 |
| 输出长度 | 载体负责续写与无缝拼接 | 受单次输出上限约束 |
| 工具能力 | 用户可自行添加插件，能力不封顶 | 取决于服务方提供的工具集 |
| 数据位置 | 全部在本机，离线可用 | 数据离开本机 |
| 单次成本 | 无按次计费 | 按 token 计费 |
| 可替换性 | 换模型不改配置、不丢数据 | 换服务方通常需要改造 |
| 可检查性 | 每一层（检索、补刀、校验、治疗）都有日志与测试 | 通常不可见 |
| 上限 | 载体补不了的难题仍需更大模型 | 未标注 |

不可比的维度（例如"回答质量"）不在此表中比较：没有同一套评测集与同一批题目的对照实验，
任何结论都会是编造。项目内的实测数字只覆盖本项目自身的能力项，见
[`testing-report.md`](testing-report.md)。

## 4. 系统要求与安装方式

### 4.1 系统要求

- **操作系统**：Windows / Linux / macOS 均可（主力开发环境为 Windows）。
- **Python**：3.10 及以上。
- **硬件**：消费级配置即可运行，从低配到高配均可，随配置提高可换用更大的火种模型。
  项目不把能力绑死在某个具体硬件规格上。
- **网络**：联网可用全部能力；离线时降级为本地能力（记忆、工具、续写、健康系统均不受影响）。

### 4.2 安装

```bash
git clone https://github.com/jiangchuangege/xiaojiao-harness.git
cd xiaojiao-harness
python start_xiaojiao.py
```

启动后按终端提示访问本机地址即可。详细步骤、依赖清单与故障恢复见
[`install.md`](install.md) 与 [`quickstart.md`](quickstart.md)。

## 5. 本版主要改动

### 5.1 修复

| 改动 | 现象 | 处理 |
| --- | --- | --- |
| 思维流假记忆 | 问"我叫什么名字来着？"，画像被存成"名字：什么名字来着"，随后顶掉正确答案 | `core/mind_stream/update.py` 增加疑问句判据，画像只由陈述句更新；`tools/test_mind_stream.py` 66/66 |
| 小脑长文本失效 | 长文本里改一个字，余弦仍在 0.99 以上 | `core/embedder.py` 空间 v3：截断 512→1024、去因果掩码、尾窗加权池化、分块编码、分值标定；`tools/test_embedder_long.py` 18/18 |
| 行内代码样式 | 回复里的 `` `xxx` `` 渲染成"带边框、样式奇怪"的方块 | 对齐 GitHub 观感：半透明灰底 + 等宽 + `.2em .4em` 内边距 + 6px 圆角 + 无边框；`tools/test_inline_code.py` 13/13 |
| 数学公式不渲染 | `$$...$$` 与 `$...$` 原样显示 LaTeX 源码 | 引入 KaTeX 与 `mathify()`，三条渲染路径各扫一遍；`tools/test_math_render.py` 9/9 |
| 复读流式判据 | `test_bug3_repeat.py` 长期 17/19 红 | 定位为**测试计数器口径错误**（跨 36 次重试累加，却拿单次预算去判），改为逐次判定；生产代码未改；20/20 |

### 5.2 新增

- **检索精排（载体二次判断）**：检索出 top-K 后由大脑挑出真相关的，滤掉反义与无关。
  小脑是字级模型，实测反义对余弦 0.904，高于近义对的 0.814，单靠阈值挡不住。
  判官不可用时一律放行，绝不因为精排挂了就丢用户的记忆。见 `core/retriever.py` 的 `rerank`。
- **架构文档后半篇**：`docs/design-philosophy.md` 新增第十四至二十二节，
  每一节都标注实现状态（已落地 / 部分落地 / 设计未落地）并指向真实代码路径。
- **架构图 12 至 19**：与后半篇八节一一对应，`tools/check_mermaid.py --all` 校验 0 问题。
- **模块文档**：`docs/modules/` 下每个模块一篇独立文档。

### 5.3 兼容性

- 旧的 `xiaojiao_control.json` 直接可用，无需修改配置。
- **小脑向量空间升级到 v3**，历史记忆的向量需要用 `core/embedder.py` 的 `reembed_store()` 重算一次。
  迁移器会先整文件备份、再原子替换，任意一条算不出来就整批放弃。本次实测迁移 1002 / 1002 条。

## 7. 已知限制

- **小脑向量化的三条边界**：500 字差 1 字（实测 0.9995）受固定维度池化的 `2/√N` 数学上限约束；
  反义（0.904）与无关（0.570）受字级表示约束。三条均为当前技术路线的固有上限，不是实现缺陷。
  载体的补法是检索后由大脑精排。
- **复读检测的流式路径在生产环境从未被触发**：测试覆盖了它，真实对话里尚未出现持续复读的现场。
- **未落地项**：语义缓存、批处理、投机解码、自我改进闭环、面向用户的显式告警、
  设置页的系统状态面板。这些在设计文档中均明确标注为"设计，未落地"。
- **数学公式依赖 CDN**：完全离线时降级为显示 LaTeX 源码。
- **联网用例依赖当天数据**：NVD 漏洞聚合可能按当天返回内容跳过一项。

## 8. 升级说明

1. 拉取代码后重启即可，配置无需改动。
2. 首次启动会重建小脑向量索引；如记忆库较大，建议先执行一次 `reembed_store()`。
3. 插件作者注意：工具名必须全局唯一，重名会被跳过并写 WARNING 日志（内置优先）。
4. 行为变化：说了网址会直接抓取；说画图会走 archify 工具链；同一工具连续 2 次调错会停下并如实报错。

## 9. 路线图

- **短期**：把"设计，未落地"的六项按优先级补齐；为检索精排增加可配置的触发阈值。
