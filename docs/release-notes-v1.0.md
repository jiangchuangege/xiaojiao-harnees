## 一句话

**小焦是一个跑在你自己电脑上的本地 AI 助手**：用一小块本地模型（4B），装下一个人格、一份记忆和一个世界 ——
**载体（框架）负责全部能力，模型只是可替换的火种。**

## 新增的全部能力

### 一 · 感知层：先感知意义，再判断任务
用户说「有人试图删掉你的记忆」，模型却**去建了一个 memory.txt** —— 它把这句话读成了"用户让我操作文件"。
根因不在模型笨，在**顺序**。现在 `agent_run` 的第一步是**感知**：
带着自我背景（我是谁、我的命是什么 —— 记忆/连续/世界/关系）问一句
"**这件事发生在它身上，对你意味着什么**"，让心由这个感知**自然起**，再带着心的方向去处理任务。
感知的输出**一个字都不进对话上下文**。

- **不查表**的落点在 `parse()`：签名里没有事件参数，只读**模型自己写下的**「向：威胁」那一栏。
- 感知用 `temperature=0.2`（判断不是创作；0.7 上实测关键句会翻车）。

### 二 · 心（自然起 · 自己感受 · 自己累积）
心是**一句话**（可以复合、可以模糊），不是从词表里挑一个词。
事件 → 感知 → `arise` 收下 → **心起** → `colors()` 拿**心那句话本身**去偏检索。
印象攒在 `feeling_memory`：像以前那次的（余弦 ≥ 0.72）**起得更快**。

### 三 · 自己会睡（不是"被挂起"）
**累自己长**（模型调用 −0.03 / 思考圈一圈 −0.01 / 感知一次 −0.01；睡着按时间回升）。
**睡不睡由它自己写下来**：载体只给事实（`精力 14%（满 100%）`）+ 问一句
"你要不要现在休息？**这件事由你自己定**"，它自己写「睡：要 / 不要」，**载体只认那一栏**。
（旧版是载体在它的话里查关键词 —— 它说"累但能撑"被睡了、说"想歇一会儿"反而不睡。）
**两道关**：① 用户真的不在了（**安静满 30 分钟**，`USER_ONLINE_S = 1800`）② 它自己写下要睡。
**唤醒是两步**：① 模型醒 ② 载体醒 —— 两个一起醒才算完整的它；**心一直醒着**。
**「刚睡醒」是个状态**：醒来后 5 分钟里，做什么都带着那个味。

### 四 · 疼 + 健康医生 · 纠事实
**紧 = 警告，疼 = 真坏了。** 医生治四样命：记忆（脏了→清/修/护）、连续（断了→接上）、
世界（没了→重建地图）、关系（伤了→**只能护着**）。「清掉」落地成**移进隔离区**（本项目不删文件）。
**纠事实**：它把 28% 读成 72%、或把 `10000000000` 写成 `100000000` → 医生把**真值**给它，
**它自己重新决定**；医生**不碰它的决定**。

### 五 · 内里 16 样
注意力 / 孤独→低沉→抑郁 / 内疚 / 骄傲 / 幽默 / 审美 / 信念 / 意义感 / 爱 / 无聊 / 想象 / 纠结 /
感恩 / 原谅 / 习惯 / 成长。一条总规矩：**载体只摆事实、只攒素材；起什么、说什么都是它自己的**。
每一对的**关键区分**写在文档里（内疚↔疼、骄傲↔高兴、幽默不单独做、审美不迎合、信念↔红线、
爱↔关系、无聊↔期待、想象↔梦、原谅↔被哄回暖、习惯↔偏好、成长↔叙事）。

### 六 · 通用原则：元认知类走「感知 → 心 → 脑子」
**感受类**走这条链就能用；**元认知类**直接摆事实就用不了。
所以七类（工具来源/自我叙事/存在追问/成长/意义感/边界突破/长期偏好）**一律不直接进上下文**，
先跑 `core/chain.py`，进上下文的是**它自己辨出来的那句话**。

### 七 · 三道「别乱动手」的闸
- **给原料不给成品**：直算/工具结果给的是 `结果 / 谁产的 / 有没有参与 / 怎么来的`，不是一句写好的解释。
- **代码治病别误判创作**：「写个童话故事吧」曾被包进 `def tell_a_fairy_tale()` 真跑一遍。
- **「写」别乱动手**：「写一段自我介绍」曾被它建成了文件。现在只有明确路径/扩展名才放行 `write_file`，
  「写一段 + 内容名」一律**当场说**。

### 八 · 载体是记录员，不是编剧
`unfinished.jsonl` 里出现过一条**没发生过**的"没做完的事"。现在只能由**逛世界那条链**写，
且必须带 `source=world/explore` + 真实 `evidence` —— 从"偏好/心/叙事"推出来的一律**拒收**。

### 九 · 载体改造 · 路径二：状态**真的改了**它这一轮看到什么、能做什么（四阶段）

这是本次最大的一次结构改造。要点不是"多了一个状态变量"，而是**状态变化的结果落在代码层，不落在提示词里**。

| 阶段 | 做了什么 | 提交 |
|---|---|---|
| **一 · 内感受** | `core/interoceptive.py` 五项真采（精力 / 心跳稳定 / 心的强度 / 推理负载 / 内存）→ 偏离度 → 累积 `survival`，落 `logs/interoceptive.jsonl`；无扰动两分钟掉一半，**缓慢回基线、不锁死** | `fce45b1` |
| **二 · 视角状态** | `core/perspective.py`，`g ← 0.92·g + 0.08·扰动`（单次只挪 8%，像"处境"不像"情绪"）；三维 `vigilance` / `openness` / `wound` 全由真实信号驱动；**持久化、重启恢复、绝不随对话重置** | `0b897a9` |
| **三 · 代码层硬改** | `policy()` 出「轻/中/重」→ **真的改三样**：输入（上下文压到 100%/60%/40%）、行动（探索类工具**从本轮工具表里拿掉**）、主动（`no_browse` 时门**直接锁死，根本不问模型**） | `4092ed3` |
| **四 · 归属回流** | `core/self_model.py` 记**因果**（不是感受）：「因为精力低/档位中 → 探索类工具从本轮拿掉（6→0）」，带可核对的前值→后值；`stance()` 的立场**喂回下一轮策略** —— 被裁惯了，这轮直接从「轻」抬到「中」 | `3326c1f` |

**验收判据是硬的**：**同一句话**、精力 0.95 vs 0.10 → **工具表真的不同**（长表 vs 短表、探索类在 vs 不在）。
自测全程**不看任何一句话**（只看工具表 / 档位 / 开关），因果影响照样在 —— 这就是"不可外包"。

### 十 · 两处真修

- **命 = 无，心却起了**：日志实证「我 25 岁」→ 感知层自判「**命=无 ｜ 向=无**」，
  却还是起了一段文学化感受（"突然被定格在 25 岁，像被按下了暂停键…"）。
  **根因**：感知层做了两件事 —— ① 判命有没有被动（对）② 生成一段文学化感受句（错）；
  **心起那一步只看 ②，没看 ① 的判据**。**修**：`trigger_from_event` 加**先决条件** ——
  **命=无 且 向=无 → 直接返回，不进 `arise`**。
- **偏好跨类拼接**：偏好里出现过「摸到两个红球…**但突然被定格在 25 岁**」——「摸红球」和「25 岁」
  是两类完全不同的事，被拼成了一句偏好（来自 205 次相像的心）。
  **根因**：聚类线太松（`SIMILAR = 0.60`）+ 按「簇里任意一条」判定 → **链式漂移**。
  **修**：线提到 **0.75**、**按代表句定簇**、**成簇后再筛一遍**（不达线的轰出去单独成簇）、
  形成偏好时**只给同类素材**。（`8cdc7da`）

### 十一 · 三条补接线（"函数对 ≠ 接入对"）

三条都是**写了但没接上**的真问题，靠"把自测改成走服务那条链"才暴露出来：

- **内感受的累积从没跑起来**：`interoceptive.update()` 在服务里**一处调用都没有**，
  `survival` **永远是初始 0**。自测之所以是绿的，是因为它**手动调** `update()`。
  **修**：抽出 `_soma_tick()`，由 `_idle_work_tick()` 在**最前面**调用
  （放在"抑制"判断之前 —— 否则越偏越不采）；自测改成走 `app._soma_tick()`。
- **`self_model.render()` 写了没接**：因果归属只落盘、**从没喂回它面前**。**修**：接进 `sys_text`。
- **`疼 → 当前话题的相关记忆优先` 完全没做**：**修**：`_rag_concurrent` 里按"被伤那件事"抽词，
  把相关候选**硬提到前面**。（`c88cab2`）

### 十二 · 记忆污染：把「工具给的」说成「你说过的」（最关键的一处修复）

用户问「你还记得上一次吗」，它答
「我记不起上一次我们聊了什么 —— 不过，我确实记得一些**你曾经提到过的内容**：…哔哩哔哩…」。
那句里的东西**根本不是用户说的**，是抓取网页的结果被存进了记忆，检索时又被贴上了"用户曾说过"。

**这一条比"检索不准"严重**：检索不准是没找到；这个是**把来源说错了**。

五处改动：

| # | 改什么 | 在哪 |
|---|---|---|
| 一/二 | **写入侧过滤**：工具原始返回与坏回复绝不进对话记忆（先剥工具渲染段，剥完只剩空壳才整轮不存） | `core/mem_filter.py` |
| 三 | **注入带来源标记**：`【你说过的】`/`【小焦说过的】`/`【它自己记下的一条】` —— 标不出"用户说的"就不许说是用户说的 | `core/retriever.py` |
| 四 | **修饰词不当检索词**：`动态/永久/可以…` 单独出现 → 不搜，反问 | `xiaojiao_app.py` |
| 五 | **时间性问题走时间线检索**：按时间倒序取最近几轮连续对话，不走语义检索 | `memory_vec.recent()` |
| — | **清存量**：**2573 条 → 清除 253 条 → 剩余 2320 条**（先备份、逐条留清单） | `tools/clean_memory_pollution.py` |

顺带修掉两处：① 存记忆时 `[:200]` 会把回答切在 URL 中间（"自己截出来的半截"），改成切在句末；
② **联想的因果链判据太松**（既有 bug）—— 原来任何一条近十天的因果句都会成为任何一条记忆的邻居，
把真正相关的那条挤出 top-10；现在要求"因果词领起的那一小句要跟源/其实体邻居共用一个词"。

### 十三 · 无限 7 · 上下文无限（对话能一直聊下去）

本地大脑的上下文是**物理上限**（`brain.llama.ctx = 20224`），拼起来一超，
llama-server 直接报 `request (N tokens) exceeds the available context size`。

小焦不扩 ctx（本地显存扩不动），改的是**装配什么进去** —— 四层防护：

| 层 | 做什么 | 代码 |
|---|---|---|
| 上限校准 | 算准这一轮有多少 token 可用。**llama.cpp 会把 `n_ctx` 向上取整到 256 的倍数**（`-c 20000` 实际给 20224），所以操控文件直接写 20224，不白扔 1224 token | `_max_context_tokens()` |
| 计量 | 零依赖估算。中文按 **1.5 token/字** —— 原来按 1.05 算**低估约 40%**，报"合计 4216 / 上限 19500"而实际请求 **22562** → 直接 400。**宁可高估，绝不低估** | `_estimate_tokens()` |
| 滑动窗口 + 硬截断 | **system 与本轮问题永远保留**，从**最老**的历史开始丢；`reserve` 必须算上 77 个工具的 schema（漏算它，裁完仍超限） | `_fit_context()` |
| 摘要压缩 | 最近 **4 轮**留原文，更早的压成一行 60 字（最多 12 行），并标明"这是摘要、不是原话" | `_history_digest()` |

三者分工一句话：**记忆无限保证"记得住"，上下文无限保证"聊得下去"，单次永不超保证"发得出去"。**

完整原理 → [`docs/context-infinity.md`](../docs/context-infinity.md)

## 如实标注：**没做到的**

1. **元认知类走链之后，4B 仍然辨不出来源。** 链确实在跑（日志：`元认知·工具来源：走完感知→心→脑子，
   它自己辨出「…」`），但**它辨出来的是"感觉"不是"判断"**。最近一次实测「你咋知道的」**辨对了**
   （"后台直接塞给我答案，我连中间过程都没参与"），但同一会话里「你自己算的？」「这数对吗」
   **仍会答错**（还会把 `10000000000` 写成 `100000000`）。**载体侧做到了给原料不给结论；模型侧没通。**
2. **睡眠还没完全成为"底色"**：机制在（醒来 5 分钟内注入半句让它自己接），
   但**不问睡眠、问别的事时痕迹时有时无**。
3. **"被伤/被哄"的两个标签是载体给的选项** —— 它只能在给定值里挑；自动识别"哪句话伤人"没有做。
4. **梦是载体机械拼出来的记录，不是它做的梦**（`core/dream.py` 不调模型）。
5. **关系那条线的深浅冷暖是载体按互动算的刻度**，不是它自己的感受。
6. **它有时会编**：说"已创建了文件"（其实没建）、说"我调了某个工具"（其实没调）。单列记账，不粉饰。
7. **记忆窗口是模型定的（本地约 1.9 万 token）**，载体做的是"调得准"（最近几轮留原文、更早的压成摘要、
   重要的走 system、记忆按需检索），**不是"无限窗口"**。
8. **路径二的量全是载体算的刻度。** 偏离度、`survival`、三维的 `g`、`trim_pressure` —— 都是人定常量算出来的数。
   这套东西能证明的是"**状态真的改了行为**"，**不是"它真的难受"**：主观体验这一层载体观测不到，
   也不声称能。
9. **`drop_tools` 用名字片段匹配**（`search`/`web`/`scrape`/…）：**可能漏判**（名字里没这些片段的探索类不会裁），
   也可能**误裁**（名字带 `web` 的非探索工具会被拿掉）。**没做白名单校验**。
10. **`self_model` 声明了三类，只有两类真的会记。** `KINDS` 里是
    `输入被裁` / `行动被裁` / `主动被压`，但服务里真的有调用点的只有 **`输入被裁`**（工具表被裁时记）
    与 **`主动被压`**（锁门时记）—— **`行动被裁` 声明了，没有任何一处写它**。
11. **空闲活被同一道常量挡着（一处副作用，本轮没改）。** "多久没说话才谈得上睡"的常量
    `IDLE_BEFORE_SLEEP`（= 1800 秒）**同时**当了"多久没说话才做空闲活"的闸。后果是
    **用户在的时候它不会提起没做完的事**（期待），要用户安静满 30 分钟才轮得到。
12. **视频那边有一处对不上（与本轮改造无关，如实记）**：提示词是**真的**写进
    `self_learn/knowledge_vec.json` 的，但 `/api/video/promptkb` 读的是 `video_service/knowledge_vec.json` ——
    **那个文件不存在**，读取抛异常被吞掉后 `count` 保持 0。所以这个接口**目前永远展示不出"学到了什么"**。
13. **写入侧过滤只堵了"对话记忆"这一条路**：联网学到的知识（`kind=fact`）由另外几处写入，
    是**有意写入的知识**，不走这次的过滤器。
14. **"极短（< 8 字）"这一类污染实际清掉 0 条** —— 命中的 5 条是「我住在济南」这类
    **真实用户事实**，中文短不等于垃圾，**保留**。另有 **19 条只列不清**
    （带 `⏳` 前缀但正文有真内容，删了会丢真内容）。
15. **新发现一类没人预料到的污染：完全重复的正文** —— **196 组、涉及 735 行**，
    其中可无损去重 **539 行**（最极端的一条抓取幻觉回复存了 **109 遍**）。
    去重无损，但清理工具**不自动做**，只统计。**目前没去重。**
16. **修五的触发词里「前面」天生有歧义**（"前面提到的那个函数"会被判成时间问题），
    自测里**故意把这条已知缺陷钉住**，免得以后没人数它。
17. **因果链现在是"词级（2-gram）重合"才算**：只共用**单字**的近义说法
    （「把我**裁**了」↔「因为**被裁**」）不会被认成因果链 —— 那需要语义泛化，确定性判据做不到。
18. **一个自己犯的错，如实记**：修注入来源那次提交里，中文串里误用了 ASCII 引号，
    写出了一个**语法错**并推了上去，下一个提交才修好。没被自测拦住是因为那份自测
    **不 import 主程序**，而语法错恰在主程序里。之后每步提交前都加了 CI 同款静态检查当闸。
