## 1. 扩展点总览

| 想加的东西 | 用什么 | 生效方式 | 详见 |
| --- | --- | --- | --- |
| 一个新工具 | 往 `plugins/` 放 `.py` / `.js` / `.json` | 重启小焦 | [插件开发指南](PLUGINS.md) |
| 一份长期知识或行为规范 | 往 `plugins/` 放 `.md` 技能文档 | 重启小焦；内容进入系统提示词 | [插件开发指南](PLUGINS.md) 第 3 节 |
| 说话方式、角色设定 | `xiaojiao_control.json` 的 `role` | 保存后热更新（也可在网页设置里改） | 本文第 5 节 |
| 温度、回答长度、上下文窗口 | `behavior.temperature` / `behavior.max_tokens` / `brain.llama.ctx` | 保存后热更新 | 本文第 5 节 |
| 另一个大脑 | 「设置」→ 模型管理 → 添加 | 即刻出现在顶部下拉框 | 本文第 6 节 |
| 让别的程序用小焦推理 | `/v1` OpenAI 兼容接口 | 无需改动小焦 | 本文第 7.1 节 |
| 在脚本里调用小焦的工具 | `xiaojiao_tools.py` 的 `POST /api/run` | 需单独启动该服务 | 本文第 7.5 节 |
| 让模型直接生成插件代码 | `POST /api/plugin/generate` | 生成后自动注册 | 本文第 7.6 节 |

## 2. 写插件

小焦启动时扫描 `plugins/`，凡是提供 `get_tool_descriptions()` 与 `execute()` 的类都会自动注册成可调用工具。最小示例：

```python
# plugins/my_time.py
import datetime


class MyTimePlugin:
    def get_tool_descriptions(self):
        return [{
            "name": "get_time",
            "description": "返回当前时间",
            "parameters": {"type": "object", "properties": {}},
        }]

    def execute(self, name, params):
        if name == "get_time":
            return datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        return None
```

放进 `plugins/` → 重启 → 工具进入清单。参数声明、返回约定、命名冲突与异常处理等完整契约见 [插件开发指南](PLUGINS.md)。

## 3. 工具型与数据型

| 类型 | 作用 | 例子 |
| --- | --- | --- |
| 工具型 | 让模型"动一下"：产生副作用或取回实时结果 | 查天气、算数、查 IP、发请求、截图 |
| 数据型 | 给模型"多一份知识或渠道"：提供它本来不知道的内容 | 读配置文件、查数据库、拉内部接口、检索本地资料库 |

两者写法相同，区别在于 `execute` 里做什么、返回什么。

## 4. 插件点子清单

下表是可直接照抄改造的方向，具体实现自行取舍。

| 方向 | 做什么 | 实现要点 |
| --- | --- | --- |
| 计算器 | 数学求值 | 白名单校验字符后求值，或引入符号计算库 |
| 翻译 | 中英互译 | 调用翻译接口；注意限流与超时 |
| 查 IP | 公网 IP 与归属地 | 参考 `plugins/ip.json` |
| 二维码 | 生成二维码图片 | 生成 PNG 后返回文件路径或链接 |
| 汇率 | 外币换算 | 调用汇率接口并缓存当日结果 |
| 备忘录 | 记录一条到本地文件 | 读写 JSON / 文本文件 |
| 定时提醒 | 到点提醒 | 后台线程或任务表，避免高频轮询 |
| 读系统信息 | CPU / 内存 / 磁盘 | `psutil` 等已安装库 |
| 生成图片 | 调用图像接口出图 | 返回可访问的 URL 或本地路径 |
| 网页摘要 | 抓取并摘要 | 抓取可复用 `plugins/scrapling_bridge.py` 的现有工具 |

注意：

- 用到的库要显式 `import`，且必须是环境里已安装的；
- `execute` 同步执行，不要写长时间阻塞的操作；
- 插件抛出的异常会被捕获并返回空串，需要可读报错就自己转成中文文本。

## 5. 改人设与行为参数

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 人设 | `xiaojiao_control.json` → `role` | 写清"是谁、怎么回答、要不要用工具、下指令时用什么文件名"。网页「设置」里可改，保存后热更新 |
| 采样温度 | `behavior.temperature` | 越高越随机 |
| 回答长度上限 | `behavior.max_tokens` | 单次回答的 token 上限 |
| 上下文窗口 | `brain.llama.ctx` | 本地大脑的上下文窗口，默认 20224 |

系统提示词由 `compose_system_prompt()` 统一合成：人设 + 检索规则 + 工具规则 + 动态工具清单 + 技能插件内容 + 人格规则。每条规则只拼一份，所以改 `role` 不会把工具清单或检索铁律弄丢。

## 6. 加模型

「设置」→ 模型管理 → 添加，填写：名称、类型（`api` 外接 OpenAI 兼容 / `llama` 本地 / `xiaojiao` 自建）、BaseURL、API Key、模型名。保存后出现在顶部下拉框，可随时切换。

- 切换的是底座大脑，人设、工具、记忆都跟着壳走；
- 本地 GGUF 可走 `POST /api/model/addlocal` 一键登记（会同步写入 `llama-swap.yaml` 与大脑注册表）；
- 云端 API Key 可以只放在环境变量 `XIAOJIAO_API_KEY` 里，或把控制文件的 `api_key` 写成 `env:变量名`。

## 7. 进阶玩法

### 7.1 当外挂大脑

小焦的 `/v1` 是 OpenAI 兼容接口。任何支持自定义 API 地址的 Agent 框架、工作流或机器人，只要把模型地址填成：

```text
http://127.0.0.1:5000/v1
```

就能用小焦推理：框架负责调度与流程，小焦负责人设、工具与记忆。可用的端点只有 `GET /v1/models` 与 `POST /v1/chat/completions`（后者支持 `stream`）。

### 7.2 多工具串联

写若干个各司其职的插件（查天气、记备忘、查时间各一个），不需要在代码里规定调用顺序。把"要达成什么"写进 `role`，模型会自己先调前置工具、看到结果后再决定下一步。前提是每个插件的 `description` 写清"什么时候用、输入什么、输出什么"。

### 7.3 接外部系统

把已有 HTTP 接口包成插件：`execute` 里请求该接口，把返回整理成一段可读文本再交回模型。步骤是"读接口文档 → 在 `execute` 里发请求 → 把结果转成文字"。凭证从环境变量读取，不要写进代码或提交进仓库。

### 7.4 加记忆分支

小焦本身会把学到的内容写入记忆。需要自己的持久化（偏好、标签、某类数据）时，在插件里读写自有文件即可，不必改动记忆模块。长期记忆的注入条数与阈值由 `capabilities.memory_top_k` / `memory_threshold` 控制。

### 7.5 当命令行执行器

`xiaojiao_tools.py` 提供独立端口上的工具调用服务（默认 5003，需单独启动）：

```powershell
python xiaojiao_tools.py
```

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/` | GET | 可视化面板：列出工具、填参数即执行 |
| `/api/tools` | GET | 返回该服务内置的工具说明清单 |
| `/api/run` | POST | 执行一个工具，请求体形如 `{"name": "run_command", "command": "..."}` |

该服务默认只监听 `127.0.0.1`（`XIAOJIAO_TOOLS_HOST` 可改，端口用 `TOOLS_PORT`），且只有本机回环请求的 `force` 才会被接受：非本机请求即使传 `force` 也会降级走确认流程。

### 7.6 让模型写插件

`POST /api/plugin/generate` 接受自然语言需求，用编码大脑生成插件代码并尝试注册；生成失败时返回模板。适合快速搭一个草稿，代码质量仍需人工复核。
