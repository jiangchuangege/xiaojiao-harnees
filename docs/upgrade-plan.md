## 1. 定位与差异点

| 维度 | DeepSeek Harness | 小焦 |
| --- | --- | --- |
| 目标用户 | 开发者与技术团队 | 普通使用者 |
| 安装方式 | 需要 Node 环境与手工配置 | 一键安装脚本 |
| 成本结构 | 全云端按量计费 | 本地推理为主，复杂任务才走云端 |
| 插件生态 | DSH 插件体系 | 兼容 DSH 工具型插件、OpenAI function-calling、Claude tool-use，并支持自然语言生成插件 |

小焦是本地优先的桌面 AI 助手框架：以本地模型承担日常对话与工具调用，用云端模型兜底复杂任务，
插件放进目录即可生效。

## 2. 阶段一：技术实现

计划周期：第 1–2 月。

### 2.1 零门槛安装

**目标**：把「配置」变成「对话」，全程不需要手改文件。

| 计划项 | 现状 |
| --- | --- |
| 硬件自动检测 | **部分落地**：`install_all.py` 第 8 步用 `nvidia-smi` 检测显卡名称；显存、内存、硬盘、网络未纳入 |
| 按显存分档自动推荐模型 | **设计，未落地**（例如 8G 推荐 8B、4G 推荐 4B、无显卡转 CPU 或云端），当前是「全盘探测已有模型 + 手填任意端点」 |
| 自动下载模型 | **部分落地**：llama.cpp、llama-swap、Wan2.1 三件套可自动下载；国内镜像只有 hf-mirror。断点续传、校验和验证、下载后试生成一次均**设计，未落地** |
| 一键写配置 | **已落地**：`install_all.py` 第 9 步写入 `xiaojiao_control.json`（`keep_warm`、ComfyUI 路径等） |
| 安装完成后由桌面端 N.E.K.O. 播报结果 | **设计，未落地** |

**风险与应对**

| 风险 | 应对 |
| --- | --- |
| 下载慢或中断 | 多镜像 + 断点续传 + 自动重试（当前只有单镜像与单次下载） |
| 硬件太老或不兼容 | 自动降级：CPU 模式 / 纯云端模式 / 无模型对话 |
| 磁盘不足 | 下载前检查空间，提示清理或改用更小的量化版本 |

### 2.2 智能调度

**目标**：本地省钱、云端兜底、成本透明。

| 计划项 | 现状 |
| --- | --- |
| 按任务复杂度路由（闲聊走本地小模型，编码走本地编码大脑，复杂推理走云端） | **部分落地**：`brain.engine` 支持 `llama` / `auto` / `api` 三种取值，多大脑注册表与秒级切换已落地；**按复杂度自动打分并路由的设计未落地** |
| 复杂度判断器 | **设计，未落地** |
| 云端超时或断网自动降级到本地 | **已落地**：云端连续失败 3 次进入冷却，改用本地大脑 |
| 成本看板（每次云端调用记 token → 换算金额 → 显示今日节省） | **已落地（基础版）**：`GET /api/cost` 返回调用数、本地与云端 token、花费与相比全云端的节省；主界面顶栏有「今日节省」角标 |
| 用户可强制本地或强制云端 | **设计，未落地** |

**风险与应对**

| 风险 | 应对 |
| --- | --- |
| 误路由导致简单问题走上云端 | 置信度阈值 + 允许使用者强制指定（阈值部分未落地） |
| 云端限流、延迟、断网 | 超时自动降级本地 + 重试 + 本地缓存（熔断部分已落地） |
| 使用者不信任自动上云 | 默认本地优先；上云前可先提示预估费用（提示未落地） |

### 2.3 插件万能桥

**目标**：统一三种工具协议，并支持用自然语言生成插件。

| 计划项 | 现状 |
| --- | --- |
| 统一工具协议（DSH 插件、OpenAI function-calling、Claude tool-use 归一到内部工具描述） | **部分落地**：工具合成入口已存在（`xiaojiao_app.py` → `_make_tools_plugin`）；DSH 的功能型（工具）插件可独立兼容，不需要安装 DSH |
| 适配器层 `adapters/dsh`、`adapters/openai`、`adapters/claude` | **设计，未落地**，仓库中目前没有 `adapters/` 目录 |
| 插件放进 `plugins/` 即自动扫描注册，界面可开关 | **已落地**：`load_plugins()` 扫描 `plugins/`，支持 `.py` 工具插件、`.json` API 插件、`.md` 技能插件三类，并带启用开关 |
| 自然语言生成插件（说出需求 → 生成代码 → 写入 `plugins/` → 注册 → 可用） | **设计，未落地** |

**风险与应对**

| 风险 | 应对 |
| --- | --- |
| 各生态的参数格式不同 | 适配器层统一 schema（含参数类型规范化；该修复已落地在现有插件加载路径） |
| 恶意或低质量插件 | 沙箱运行 + 权限确认（`run_command` 等危险命令默认需要确认）+ 插件来源评分（前两项已落地，评分为设计项） |
| 生成的插件有缺陷 | 生成后自动做语法校验并试调用一次再启用（设计项） |

## 3. 阶段二：产品体验

计划周期：第 2–3 月。

| 计划项 | 现状 |
| --- | --- |
| 对话即配置（使用者说「我要离线隐私 / 显存小 / 要省钱」，自动切换大脑与调度策略） | **设计，未落地** |
| 成本看板页（每日节省、云端调用次数、柱状图、Top 提问） | **部分落地**：`GET /api/cost` 与顶栏角标已有；柱状图与 Top 提问未落地 |
| 插件市场页（卡片式一键安装） | **设计，未落地** |
| 桌面端 N.E.K.O. 集成 | **已落地**：`install_all.py` 会探测 N.E.K.O. 安装位置，详见 `docs/neko.md` |
| 新手引导（首次启动三步：选场景 → 自动配置 → 试一句话） | **设计，未落地** |

**风险与应对**

| 风险 | 应对 |
| --- | --- |
| 功能过多导致普通用户不知从何入手 | 渐进式界面：新手模式（场景卡片）与高级模式（全功能） |
| 使用者不知道能做什么 | 场景化预设：写作业、整理文件、查资料等一键场景 |
| 成本数字不准确 | token 按官方价换算，并在界面标注「估算」 |

## 4. 阶段三：社区运营

计划周期：第 3–6 月。

| 计划项 | 现状 |
| --- | --- |
| 开放插件 SDK（文档 + 模板仓库 + 示例） | **部分落地**：插件格式与用法已有文档 `docs/PLUGINS.md`；模板仓库与示例集未落地 |
| 官方先发布 20 个插件（天气、新闻、文件、代码、翻译、音乐等） | **部分落地**：仓库内现有天气、搜索、记忆、音乐、视频、代码智能、资产测绘等插件；数量未达计划值 |
| 插件大赛与月度评选 | **设计，未落地** |
| 对外传播（教程与视频分发） | **设计，未落地** |
| 一键安装器与桌面端 N.E.K.O. 作为演示素材 | 一键安装已落地；演示素材属运营事项 |

**风险与应对**

| 风险 | 应对 |
| --- | --- |
| 缺少插件贡献者 | 官方先出示例与模板 + 激励 + 降低门槛（自然语言造插件） |
| 插件质量参差 | 评分、审核、沙箱 + 官方推荐标记 |
| 社区冷启动 | 先用零门槛安装与低成本运行吸引普通使用者，再引导开发者 |
