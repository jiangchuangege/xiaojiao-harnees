### 2.3 「248 / 249」与跳过项的口径

上一轮机读落盘结果保存在 `tests/stress/results.json`（生成时间 2026-09-14 19:52:56），记录为 248 / 249、通过率 100.0%、耗时 101.0s，其中 1 项为跳过。

- **跳过项**：「联网」套件的用例「软件名可读性（CPE→人话）」。
- **跳过原因**：当天 NVD 返回的 5 行 CVE 记录均未收录 CPE 产品配置，没有真实软件名可供校验，属数据侧缺项，而非代码缺陷。
- **该项不是失败**：`tests/stress/harness.py` 的 `Results.pass_rate` 按「通过数 ÷（通过数 + 失败数）」计算，跳过项既不计入分子也不计入分母。所以 248 通过 + 0 失败 → 通过率 100.00%，而总数仍显示 249。跳过数由独立字段 `skipped` 记录并写入结果 JSON。
- 同一条用例在本次复跑中已执行并通过（当天 NVD 数据含 CPE，软件名列出现 `Linux Kernel` 等真实名称）。

联网套件另有两处按设计可跳过的分支：NVD 接口限流或网络不可用时，「NVD 最近 7 天高危漏洞」与「days 上限夹取 / severity=ANY」两条会记为跳过（见 `tests/stress/test_network.py`），同样不计为失败。

### 4.2 长时压测脚本

```powershell
python tests/stress/stability_30m.py --minutes 30 --interval 10
```

脚本的实际行为（见 `tests/stress/stability_30m.py`）：

- 默认 `--target both`，同时压整机（走 `POST /api/chat` 全链路）与插件直连；可用 `--target app` 或 `--target plugin` 只压一侧。
- 主循环节奏由 `--interval` 控制（默认 10 秒）；整机层每 `--chat-every` 秒（默认 90 秒）打一次真实对话。
- 监控采样每 30 秒一条：本进程内存、小焦进程内存、会话数、chrome 进程数、线程数、熔断与退避计数。
- 相位覆盖：整机端到端冒烟（6 类真实对话）、会话增长与 3 路并发、连开 25 个会话不关闭、熔断与退避、NVD 连查 4 次。
- 结束后输出人读报告 logs/stability_30m.md 与机读明细 logs/stability_30m.json。
- 判定为 FAIL 的直接证据之一是「大脑未应答、只回兜底模板」的对话次数不为 0，避免把假通过记成成功。

已知缺口：脚本默认上限为 30 分钟，未做过小时级或天级的连续运行。

## 5. 如何复现

```powershell
python tests/stress/run_all.py --offline        # 只跑离线：单元 + 应用逻辑 + 安全，本机约 11 秒
python tests/stress/run_all.py                  # 全量含联网，本机约 100~140 秒（随外站响应波动）
python tests/stress/run_all.py --quick          # 跳过并发与熔断自愈等耗时项
python tests/stress/run_all.py --json results.json --min-pass-rate 95
python tests/stress/live_check.py               # 实机验收，需服务正在运行
python tests/stress/ui_check.py --out ui_chat.png   # 真浏览器渲染检查
```

- 无网环境可用环境变量 `XJ_STRESS_OFFLINE=1` 代替 `--offline`。
- 退出码：0 表示通过率达标；1 表示低于门槛。
- 四个套件也可以单独运行，各自的用法见 tests/stress/README.md。

CI 配置为 `.github/workflows/stress-test.yml`：每天 03:00（UTC+8）运行，也支持手动触发与指定路径变更触发；通过率低于门槛时该步骤直接失败，结果文件以 artifact 形式上传统一保存 30 天。

## 6. CI 现状与历史记录

### 6.1 五道质量闸门

`.github/workflows/stress-test.yml` 依次执行：

1. `python tools/check_mermaid.py --all`（Mermaid 图语法）
2. `python tools/audit_static.py`（静默吞异常、裸 except、明文密钥）
3. `python tools/check_docs.py`（文档链接／路径／接口／工具名一致性）
4. `python -m ruff check --select E9,F63,F7,F82 .`（未定义名与语法级缺陷）
5. `python tests/stress/run_all.py --json tests/stress/results.json --min-pass-rate 95`（压力测试）

工作流内设置 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`。

### 6.2 已修复的 CI 编码缺陷

runner 控制台编码不是 UTF-8 时，`tools/check_mermaid.py` 打印中文会抛 `UnicodeEncodeError`，导致每次运行都卡在第一步质量闸门，压力测试从未在 CI 中执行。修复方式：入口脚本启动时把 stdout／stderr 切换为 UTF-8，工作流补充 `PYTHONUTF8=1`。本地用非 UTF-8 编码复现并验证修复后退出码为 0。

### 6.3 历史记录的使用限制

修复后的首次全绿运行（run 34691282396）记录为「五道闸门全部通过，压力测试 217/217」。该数字属于历史世代：全量套件的用例总数经历过多个世代，逐条对比时应以同一次运行的记录为准（详见 press-kit.md）。当前世代的本地全量为 249 项。

另外，CI 环境只安装抓取栈、requests 与 Playwright，不安装 flask 与 torch，主程序加载不了。此时应用逻辑套件按设计收敛为 1 条跳过记录，CI 的合计数因此低于本机全量；这是设计行为，不是回归。

## 7. 结论与后续

**结论**：抓取插件、应用层检索与漏洞规则、安全闸门已达可交付水平——本机全量 249 / 249、0 失败、0 跳过，无未修高危项。

**范围限制**：视频、播客、音乐、安装器与小脑训练等路径尚无自动化覆盖，项目整体属于「可运行但未完全自动化」。

**建议优先级**：

1. 为小脑推理与记忆检索补最小单测（改动频繁、回归代价最高）。
2. 给安装器加 `--dry-run` 模式后纳入 CI。
3. 跑一次完整的 30 分钟无头压测（`tests/stress/stability_30m.py`），把结果写回本报告。
4. 长期运行能力验证：把压测时长从 30 分钟提升到小时级，观察 P95 延迟是否衰减、内存是否持续增长。
5. 为 NVD 漏洞聚合接入免费 API Key（设计，未落地）：当前 `collect_vulnerabilities` 走匿名调用，无密钥时限流较严，代码只在收到限流响应时退避重试一次。规划中的开关名是 `XIAOJIAO_NVD_API_KEY`，该环境变量在代码里尚无引用，实施前不可依赖。
