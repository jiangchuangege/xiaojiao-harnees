# 难度路由：什么时候该换更"聪明"的模型

> 代码：`core/model_router.py` ｜ 自测：`tools/test_model_router.py`（20 项）｜ 接线：`xiaojiao_app.py` 的 `_llm_targets()`

## 一、先看实测：换更大的模型 ≠ 更强

同一台机器、同一句话、llama-swap 上的四个模型（2026-10-17 实测）：

| 模型 | 闲聊 | 小数比较（3.11 vs 3.9） | 写快排 |
| --- | --- | --- | --- |
| `xiaojiao`（4B，默认） | **1.2s** | 0.7s **答对** | 2.7s |
| `qwopus3.5-4b-coder` | 10.9s | 0.6s 答对 | **1.8s** |
| `coder` | 28.4s | 1.0s **答错** | 4.9s |
| `deepseek-v4` | 53.6s | 29.6s 答对 | 2.5s |

两件事必须记住：

1. **大模型在简单题上更贵、还可能更错** —— `coder` 把 3.11 和 3.9 比反了；
2. **llama-swap 切模型要重新加载**，冷启动 20~50 秒。所以"每句话都智能挑模型"会把时间全花在换模型上。

由此第一版就被现实打回来了：评测连跑 14 条不同任务 → 档位反复切换 → 4B 被反复卸载重载，
**问天气从 8.8 秒变成 99 秒**。所以路由的重点不是"更聪明"，是**少切、切得准**。

## 二、实测曲线（`tools/bench_routing.py`，同一批题 × 四个模型）

跑法：`python tools/bench_routing.py --save`（结果落 `docs/routing-bench.json`）。
判分是自动的（数学看数字、代码看 `def`/`[::-1]`、开放题看非空不超长），延迟直测 llama-swap。

| 模型 | 闲聊 | 简单事实 | 代码 | 重推理 |
| --- | --- | --- | --- | --- |
| `xiaojiao`（4B） | 100% / 1.7s | 100% / 0.3s | 100% / 2.5s | 100% / 2.8s |
| `qwopus3.5-4b-coder` | 100% / 7.3s | 100% / 0.2s | **100% / 1.1s** | 100% / 1.2s |
| `coder` | 100% / 12.4s | **67%** / 0.2s | 100% / 1.2s | 100% / 1.3s |
| `deepseek-v4` | 100% / 12.3s | 100% / 0.3s | 100% / 1.5s | 100% / 2.4s |

**这张表直接推翻了我原本的设计**，如实记下来：

1. **code 档成立**：写代码 qwopus 1.1s vs 4B 2.5s，快 2.3 倍、准确率一样 → 值得切；
2. **fast 档成立**：闲聊 4B 1.7s，换谁都更慢（7.3~12.4s）→ 简单活就该用最快的；
3. **strong 档不成立**：重推理题上 `deepseek-v4` 100%/2.4s，`xiaojiao` 100%/2.8s ——
   **准确率一样、只快 0.4 秒**，而切过去要冷启动 20~50 秒 → 净亏。
   所以 strong 档**默认关掉**（判据仍在、配置 `routing.strong=true` 可开），
   这就是"实现了 → 实测发现没用 → 默认关掉，把依据留在文档里"。

注意样本量：每类题 1~2 条，只能说明"这几类题上没优势"，不能外推成"大模型永远没用"。
要更硬的结论得把题量堆到每类 ≥20 条 —— 这是下一步（见文末）。

## 三、三档

| 档 | 用什么 | 什么时候 |
| --- | --- | --- |
| fast 档 | `xiaojiao`（4B） | 闲聊、简单事实、小数比较这类"4B 就够"的活 |
| code 档 | qwopus3.5-4b-coder → coder | 命中文档里的代码词（写函数/报错/重构/SQL/正则…） |
| strong 档（**默认关**） | deepseek-v4 → coder | 命中"重推理词"**且**题目够长（≥20 字），或题目 ≥120 字。实测无准确率收益，默认不启用 |

判据是**字面 + 长度**，不调模型（这一步必须在调用模型之前完成，且要可复现、可单测）。

## 三、四条防抖动规则（都是被实测逼出来的）

| 规则 | 为什么 |
| --- | --- |
| **同档必沿用**（粘性） | 连着问代码，不要每次都重新决策 |
| **升档立即**（fast→code/strong） | 第一版把升档也压住了，结果"第一次写代码也不切"，等于永远让 4B 干重活 |
| **降档等冷却**（默认 60 秒） | 一句闲聊就切回 fast、下句代码又切回去 → 反复冷启动 |
| **切换预算**（180 秒内最多 2 次） | 连续多任务时档位来回跳，实测把 8.8 秒拖到 99 秒 |

兜底：目标档的模型不在 `/v1/models` 里 → 退该档备选 → 再退 `fast`；
一个都探不到（服务没起）→ **返回空，调用方按原配置走**，绝不把请求发进 404。

## 四、怎么验证它真的在起作用

```bash
python tools/test_model_router.py          # 20 项：判据/粘性/升档/预算/兜底
python tools/eval_xiaojiao.py --offline    # 评测里有 4 条路由断言
```

真机看日志（一轮里只在档位或模型**变化**时打一条，不刷屏）：

```
大脑路由：fast 档 → xiaojiao（普通问题）
难度路由：句19字 → code 档，改用 qwopus3.5-4b-coder-mtp-q5_k_m.gguf（命中代码词）｜原 xiaojiao
大脑路由：code 档 → qwopus3.5-4b-coder-mtp-q5_k_m.gguf（命中代码词）
```

`_CTX["route"]` 里也留了一份，界面/复盘/后续评测都能查到"这一轮到底用了哪档哪模型"。

## 五、边界（如实说）

- **只决定"用哪个模型"**：不改工具、不改提示词、不改记忆；
- **云端大脑不换档**：配置是外部 API（deepseek/agnes）时，路由只记日志、不动手；
- **判据是字面的**：像"帮我把这个思路写成代码"（含"代码"但其实是解释）会被判成 `code` 档 —— 换错档只是慢一点，不会答错；
- **`strong` 档会明显慢**（实测 30~60 秒，含冷启动），所以只在"题目够重"时才用；
- 模型池里没配 coder 类模型时，`code` 档自动退 `fast`，不会报错。
