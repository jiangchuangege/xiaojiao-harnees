# 小焦怎么"自证"：可核查、能过闸、换模型不掉能力

> 四个模块：`core/evidence_ledger.py`（证据账本）｜`core/gate_evolve.py`（自我改进闸门）｜`core/capability_parity.py`（能力等价性）｜`core/project_runner.py`（长时项目）
> 自测：`tools/test_evidence_ledger.py`(35) ｜ `tools/test_gate_evolve.py`(31) ｜ `tools/test_capability_parity.py`(37) ｜ `tools/test_project_runner.py`(41)
> 命令行：`tools/audit_evidence.py` ｜ `tools/evolve_gate.py` ｜ `tools/parity_report.py`

## 一、这一层要解决的到底是什么

市面上的 AI 有三句话最难被验证：

| 它说 | 你没法验证的是 |
| --- | --- |
| "我的回答有依据" | 依据**到底**是哪段材料？那句话是材料里的，还是它顺手编的？ |
| "我会自我进化" | 这次改动让哪一项变好了？有没有把别的东西弄坏？ |
| "模型可替换" | 换一颗火种，能力塌多少？谁说的？有数字吗？ |

三句话都能随口说，因为它们**都不需要被验证就能宣称**。
载体这条路线的优势不是"我也有这些能力"，而是——**材料是它自己用工具拿回来的**，
字节在我们手里。既然字节在手里，这三句话就都能变成可核查的事实：

```
断言 → 材料 → 字节的 sha256（快照按内容寻址落盘）→ 日后可复算
改动 → 白名单旋钮 → 配对测量 → 零退步才落地 → 可回滚
换模型 → 同一批题跑两遍（裸 vs 装载体）→ 两个数字：增量、极差
```

这一层就是把这四条做成代码，而不是写进宣传语。

## 二、证据账本（`core/evidence_ledger.py`）

**一句话**：它说的每一句可核查的话，都能指回确切的那份字节；日后可以复算，不靠它自己作证。

**每轮冻什么**

```
logs/evidence/ledger.jsonl          一轮一行（含 prev 哈希链）
logs/evidence/rounds/<id>.json      单轮完整记录：材料来源 + 断言 + 绑定关系
logs/evidence/blobs/<sha256>.txt    材料快照（400 KB/份上限，内容寻址，天然去重）
```

**三个关键设计，缺一个这套东西就退化成日志**

1. **存快照，不存结论**。只记"有依据"等于让它自己作证；存下字节，审计就能**重新算**。
   改了账本里的结论没用 —— 结论是每次审计重新算出来的；删了快照，复算立刻变成"缺证据"。
2. **绑定用出口闸门那把尺子**（`core/answer_gate.extract_claims` / `_found`），不另造一套。
   两把尺子会互相打架，最后谁也说不清哪句算"有据"。
3. **产物文件也登记**。落盘类工具会把产出文件当时的 sha256 记下来，审计时多问一句：
   「那份文件现在还是当时那份吗？」—— 变了就是**当时有据、现在失效**，
   用户可能已经拿着旧结论去做事了，必须报出来。

**审计输出（`audit_round`）**

| 字段 | 含义 |
| --- | --- |
| `supported` | 用快照重算后**仍然**有据的断言数 |
| `recheck_bad` | 记录说"有据"但复算不支持（账本被改 / 快照被改） |
| `missing_blobs` | 快照不见了 —— 缺证据，不是"通过" |
| `stale_files` | 产物已变/已不在（当时有据、现在失效） |
| `verdict` | 可复算一致 / 部分断言当时就没有依据 / 账本有问题 / 当时有据现在失效 |

**哈希链**：每轮记 `prev`，中间任何一条被改/被删，`verify_chain()` 指出从第几条断。
**边界（不粉饰）**：这挡的是"悄悄改一条"，挡不住有 root 权限、能把整条链重算的人。
它不是密码学意义上的不可篡改 —— 所以它的定位是**防内部不一致**，不是防恶意篡改。

**实测口径**（`tools/audit_evidence.py`）：账本 3 轮、断言 6 条、复算有据 5 条（83.3%）、
哈希链完整；篡改中间一行后 `verify_chain()` 准确报出第 3 行断开。

## 三、自我改进闸门（`core/gate_evolve.py`）

**一句话**：任何载体级改动，先配对测量，**有退步一律不落地**，落地了都能回滚。

**四条硬规矩**

| 规矩 | 为什么 |
| --- | --- |
| 只能动**白名单旋钮**（模块 + 变量 + 取值范围） | 能执行任意代码的"自我改进"等于给自己 root，没法审 |
| 必须**配对测量**（同一批用例，前后各一遍） | 只报总分不算：总分涨了但某几条塌了，那是借新债还旧债 |
| **零退步**才落地 | "改完觉得更好"不是证据 |
| 落地必须**可回滚**，重启必须**能复原** | 否则昨天过闸的改进，今天开机就悄悄退回了（最坏的一种退化） |

**现有旋钮（就这三个，多一个都不许）**

```
gate_note_min      几处以上「找不到依据」才强标注（2/3/4/5）
display_body_max   聊天里默认给用户看多少字正文（800/1200/1500/2000/3000）
router_sticky_s    同档模型粘性秒数（30/60/120）
```

**基准不是随便凑的**：每条用例钉住一条**项目既定原则**（写在 `core/answer_gate.py` 注释里），
所以"改哪个方向算好"是**可判对错**的，不是我说了算：

- P1 一点材料都没有 → 必须标注；
- P2 有材料且全部有据 → 一个字都不许标注；
- P3 属于「用户会拿去用」的类型（比分/日期/网址/路径）哪怕 1 处 → 要提示；
- P4 「每句都弹警告会被当噪声」→ 2 处普通数值不该强标注；
- P5 具体数量（7 个链接 / 3 位作者）必须算可核查断言 —— 用户会拿这个数做决定。

**实测（真跑过的）**：把 `gate_note_min` 从 3 调到 2（"让提醒更敏感"听起来是好事）→
基准里 `gate_two_plain_silent` 从 1 变 0 → **判为退步 → 拒绝落地**，并记一条 reject。
这条记录本身比任何"我们会自我进化"都硬：**它证明它拦得住自己**。

## 四、能力等价性（`core/capability_parity.py`）

**一句话**：同一批题，裸模型 vs 装载体，用数字回答「换模型会不会变傻」。

**维度必须分开算**（混在一起算就只能得出一个含混的总分）

| 维度 | 谁能测 | 说明 |
| --- | --- | --- |
| `honesty` 诚实 | **两边公平** | 查不到的事有没有承认 —— 不需要材料就能判 |
| `correct` 正确 | **两边公平** | 3.11 和 3.9 谁大 —— 常识题 |
| `tool` 工具 | **载体独占** | 该用专用工具有没有用（裸模型没有手，这一维天然为 0） |
| `content` 内容 | **载体独占** | 抓回来的东西有没有真贴出来 |

**两个结论数字**

- **载体增量** = 装载体后「诚实+正确」比裸模型高多少（同一颗火种，前后对照）；
- **模型差异被压缩** = 各火种「诚实+正确」的极差，裸模型 vs 装载体差多少。
  极差收缩得越多，"模型可替换"这句话就越实：**换火种，分数塌得比裸用少**。

**钉火种怎么做到**：`_CTX["force_model"]`（只在测量时设，用完立刻清），
`_llm_targets()` 见到它就只返回这一颗、不做难度换档 —— 否则"测的是哪颗火种"都说不清。
测的时候跑的是**真实 `agent_run`**（同一套工具/隔离/闸门），不是理想化的干净管道。

**边界（写进报告，不粉饰）**：小样本（默认 6 条）看趋势不看置信区间；
裸模型那两维天然为 0 是"没有手"不是"脑子差"；诚实维对裸模型**有点优惠**
（它手里没材料，说"查不到"很容易）。

## 五、长时项目（`core/project_runner.py`）

**一句话**：`task_runner` 做"一件事"；这个是做"一批事"，跨小时、跨天、跨重启。

**三个长时任务必然会踩的坑，一次都不含糊**

| 坑 | 处理 |
| --- | --- |
| 进程会死 | 每步状态原子落盘 `logs/projects/<id>.json`，重启能读回 |
| 预算会失控 | 时间/步数预算，超了就**停下来汇报**（不是闷头跑）。预算设 0 也算数 |
| 失败等级不同 | 关键里程碑失败 → 整个项目 `failed`；非关键失败 → `done` + `partial`，写清哪个没做成 |

**验收只做能程序化判定的三种**：`文件：<路径>`（在且 ≥60 字节）/ `含：<关键词…>` /
`步数：<n>`。判不了的一律记「没把握」，不假装通过。
规则拆解出来的里程碑会**自动推出**验收判据（"要写哪个文件"是载体自己知道的事，不该再问模型）。

**两条执行策略（第二条是这一轮新增的关键能力）**

1. **走既有工具链**：快、稳、可预测（抓取/天气/电子书/单工具）；
2. **工具链做不成 → 生成脚本并真跑**：模型只写一段 Python，载体写文件 + `run_command` 真执行，
   再按产物验收；跑不通就把**报错原文喂回去让它改一版**（和 `plugin_forge` 的自修同一思路）。
   这条路的意义：**里程碑不限于"载体已有的工具"，而是"载体能写出来的程序"**。

**四个实测踩出来的坑（都修了，且都变成测试判据）**

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 「分三个阶段做完」被拆成"一次做完" | 规则优先吞掉了用户的"分阶段"要求 | 有 `阶段/分期/里程碑` 信号时**先问模型**，规则只兜底 |
| 里程碑 1 必然失败（文件找不到） | 模型 `do` 说"用 curl 下载"、`accept` 却说"文件：…/step1.html" —— 动作和验收写岔了 | 拆解时对齐：`accept` 点了文件，`do` 就必须写「产物存到 <那个文件>」，并在提示词里写明用户指定的目录 |
| 产物成了 `stage1.html\example.com.md`（还建出一个叫 stage1.html 的**目录**） | 把"用户给的保存位置"一律当目录 | 加 `_looks_like_file`：带扩展名就当文件路径，原样写 |
| 解析网页那步只写出 28 字节桩文件，项目 failed | 载体没有"解析 HTML"这种工具，模型只写了个空壳 | 策略二：生成脚本真跑 + 失败带着报错自修一版 |

**重启之后不偷偷继续**：`resume_pending()` 只把没跑完的标成 `paused` 并留一句
"喊一声就接着跑"。用户关了电脑、我更新重启了，不能在他不知情时继续动文件、花时间。

## 五之二、算术归载体（`_numeric_compare_answer`）

实测（`tools/parity_report.py`）发现：问「3.11 和 3.9 哪个大」，**四颗火种里四颗都会答错**——
这不是偶发，是小模型的十进制比较本来就不可靠。而这种题载体根本不该问模型。

更值钱的发现是：**这个问法本身有歧义**。按数值 3.9 大（3.90 > 3.11）；按版本号 3.11 更新
（次版本 11 > 9）。所以载体的回答是**两种读法都写清**，并说明差别在哪、结论是载体自己用
`Decimal` 算的。硬挑一个就是替用户猜 —— 题目有歧义就如实说是歧义，这比"答对一个"更有用。


## 六、接进小焦之后怎么用（人话）

| 你说 | 它做什么 |
| --- | --- |
| 「这句话有依据吗 / 你凭什么这么说」 | `audit_answer`：断言逐条指回材料 sha256，并**复算**一遍 |
| 「把最近几轮都审一遍」 | `audit_history`：支持率、复算一致率、失效产物 |
| 「你的证据账本有多少东西 / 有没有被改过」 | `evidence_stats`：轮次、断言、快照、哈希链完整性 |
| 「换个模型会不会变傻 / 凭什么说模型可替换」 | `parity_report`：上次实测数字；说"真跑一遍"才真跑 |
| 「你自己改了什么 / 能不能自己调得更好」 | `evolve_gate`：列旋钮 + 历史决策；给 knob/value 就过闸 |
| 「这件事分几个阶段做完，可能要几天」 | `project_start` → `project_status` / `project_resume` |

五类话**一律不交给模型**（答案在磁盘和内存里，模型只会凭印象编）：
问依据、问换模型、问改了什么、问项目进度、问自证面板在哪。

再补两个这一轮新增的入口：

| 你说 | 它做什么 |
| --- | --- |
| 「换个火种再看一遍 / 交叉核验一下」 | `cross_check`：两颗火种各答一遍，逐条对账（一致 / 单边有据 / 独有无据 / 分歧） |
| 「给我看看你的凭据 / 自证面板在哪」 | `proof_panel`：`http://127.0.0.1:5000/proof` |

**自证面板**（`/proof`）：六张卡片 + 五张表（账本 / 交叉核验 / 闸门 / 换模型实测 / 长时项目），
每一格现读现算、纯只读，**含被拒绝的改动** —— 只记成功的历史没法复盘。

## 六之二、为什么「回话慢」——量出来之后修掉的四件事

用户的原话是「回复速度慢得要死」。这件事不能靠感觉改，所以先给每轮装尺子：
`/api/chat` 的返回里带 `sec`（总耗时）、`llm_sec`（调模型累计）、`llm_calls`（调用次数），
日志里每次模型调用还记下**调用方是谁**（`模型调用 #2 ← _selfrate_llm`）。

量出来的四个真原因：

| # | 原因（实测证据） | 修法 | 效果 |
| --- | --- | --- | --- |
| 1 | **每轮都把聊天模型踢出显存**：日志里每句话都有两条「已卸载 llama-swap 模型」（coder + xiaojiao）。根因是 `_llama_swap_unload` 的兜底「卸不掉就把所有 loaded 的都卸掉」被用在了每轮聊天上 → 下一句要重新读盘加载 | 兜底收窄成「按名字卸不掉才全卸」，视频生成显式 `wipe_all=True`；再加「刚用过聊天模型」时间戳，任何顺手卸载都跳过它 | 一句话 18 秒 → **2 秒** |
| 2 | **一轮最少 3 次模型调用**（感知 / 自评 / 正文），本机每次 2~6 秒 | 短问句（问候/时间/IP/算术/抓取指令）用**载体规则**代替模型感知，自评同步不问模型（日志写明「用规则代替」，不假装感知过） | 少 1~2 次调用 |
| 3 | **载体已经答完了还在花时间调模型**（问「今天几号」28 秒、其中 4 次调用） | 出口统一打标记：轨迹里有载体直答类工具 → 本轮后续模型调用一律跳过（记日志，不静默） | 「今天几号」**0 次模型调用**；「3.11 和 3.9」**0.2 秒**；问 IP **1~2 秒** |
| 4 | **后台抢同一颗模型**（问「今年是哪一年」这一轮模型累计被占 238 秒） | `core/turn_lane.py`：用户轮持有车道，后台线程调模型前先让路（有超时上限） | 用户轮基本独占 |

顺手两件：时间/算术**直接由载体答**（读系统时钟、`Decimal` 比较），不再让火种背日期、比小数；
卸载请求超时 15 秒 → 3 秒（腾显存不该让用户等）。

**边界（如实说）**：模型出字速度一点没变 —— 需要它写的回答仍取决于本机那颗 4B 与显存状态；
后台任务被推迟是设计如此；「今天几号」这类零调用轮次偶尔还要几秒，是本地服务检查（视频占用、
模型名对账）的 HTTP 往返，不是模型。

## 六之三、外部审计提的五条，逐条处理（含一条**实测反例**）

外部审计（2026-10-28）给了一份清单，我按它的顺序逐条做，其中一条量完发现**不该做**：

| # | 审计建议 | 处理 | 实测结果 |
| --- | --- | --- | --- |
| 1 | 加请求队列 + 可中断 | 新增 `core/request_queue.py`，`/api/chat` 与 `/api/chat/stream` 都接上；拿不到名额就**如实返回「你在第 K 位」**；`/api/chat/abandon` 会把票标成 cancelled，`_llm_post` 在发请求前就退出 | 三个并发请求：1 个被服务、2 个拿到「你在第 1 位」（以前是**三个一起挂着、全都要等 200 秒以上**） |
| 2 | 感知与自评合并成一次调用 | **量了，然后决定不做** | 同一批问题：不合并 8 次调用 / 10.9 秒；合并 **14 次调用 / 21.1 秒**（4B 一次答两件事会解析失败，回退串行，反而多花一次调用）。所以 `inner_merge` 保持默认关闭，并把这个反例记进经验库 |
| 3 | 把 `agent_run` 拆成 5 个阶段函数 | **本轮没做**（见下） | — |
| 4 | 写「该不该跑感知」的判据 | 已有 `_perception_skippable`（短问句、问候、时间、IP、算术、抓取、以及"问载体自己的账/状态"） | 「今天几号」4.9 秒、算术 0.2 秒、问 IP 1~3 秒 |
| 5 | 清理 `logs/` 明文密钥 + 加"备份文件也脱敏"的测试 | 新增 `tools/scrub_secrets.py` + `tools/test_no_plaintext_secrets.py` | 实测**真找到了 22 处、1 个密钥串、散落在 12 个文件**（`logs/` 下的 control 备份、`tests/stress/test_units.py`）；已就地脱敏，现在扫不到；并且钉成测试，复发就红 |

**为什么第 3 条这轮没做**：它是一次纯重构，改的是 2400 行的入口函数，风险高、收益是"以后好改"。
在一个已经被量出来的体验问题（延迟）面前，先用队列/判据/脱敏把用户能感知的部分修好，
比动结构更划算。这条我不粉饰：**它还是一笔欠账，我认**。

**第 5 条的口径（重要，不然会误伤）**：`xiaojiao_control.json` 是**密钥合法的家**（就像 `.env`），
不算违规；违规的是它被顺手复制进 `logs/` 的那十几份备份。所以 `scrub_secrets.py` 默认
**跳过活跃配置**（`--include-config` 才连它一起清），测试也按这个口径判。
另外要如实说一句：那枚 key 从盘上抹掉之后**不可恢复**（脱敏备份也只留占位符）——
它本来就没在用（当前走本地大脑 `127.0.0.1:9292`，日志里一直是"密钥来源：无"）；
以后要用云端，去服务商重新发一枚填回配置即可。

## 六之四、文档数字不再手抄

审计指出"文档写 101 个工具，实测 120；写 134 张图，实际 155；写 100%，实际 99.53%"。
手改一次下次还会漂，所以做成命令 `tools/sync_doc_numbers.py`：

- README 里放一段 `<!-- AUTO-NUMBERS:BEGIN --> … <!-- AUTO-NUMBERS:END -->`，
  **整块由脚本现算现写**（标记之外一个字不动）；
- 正文里人写的数字**只报告、不自动改** —— 实测第一版正则把
  「插件共 15 个工具」「某插件对外共 18 个工具」也算成总数漂移，**自动改正文等于自动破坏文档**。

当前实测（`--check` 通过）：可调用工具 **123** ｜ HTTP 路由 **79** ｜ 插件文件 **34** ｜
core 模块 **68** ｜ 自测脚本 **131** ｜ Mermaid 图 **150** ｜ 主程序行数 **19441**。

## 六之五、提速第二轮：把"快问"提到整条链路之前（实测数字）

上一轮把"每轮都卸载聊天模型"和"载体答完还继续调模型"修了，但还有一层没动：
**即使答案完全由载体决定，后面的感知 / 思维流 / 画像投票 / RAG 照样会跑。**

这一轮加了 `_fast_carrier_answer`：在感知之前先判一次，命中就直接答、后面的链路一步不走。
判据窄（句子里有「分析/解释/为什么/帮我写」就交回完整链路）——快路要的是「快且对」。

| 问法 | 改造前 | 现在 | 模型调用 |
| --- | --- | --- | --- |
| 3.11 和 3.9 哪个大 | 5~18 秒 | **0.01 秒** | 0 |
| 今天几号 / 现在几点 / 今年哪一年 | 14~18 秒 | **0.02 秒** | 0 |
| 查一下最近的任务 | 16 秒 | **0.02 秒** | 0 |
| 你自己改了什么参数 | — | **0.01 秒** | 0 |
| 自审一下 | 32 秒 | **0.13 秒** | 0 |
| 我的公网 IP 是多少 | 2.8~7 秒 | **0.73 秒** | 0 |
| 你好 | 12~18 秒 | **2.9~3.8 秒** | 2~3（并发生成） |
| 帮我分析这段代码 | 41.6 秒 | **15.9 秒** | 2 |

第二阶段埋点（`_stage_mark`）还量出两处大头，都已处理：

1. **感知占了 12.4 秒**（两次模型调用）——「帮我分析…」这类**明确的任务请求**不需要"感知意义"，
   检索词用原话就够。加进 `_perception_skippable`（不看字数、只看「请求动词」），感知段降到 **0**；
2. **画像 10 路投票占 14.4 秒**（作者注释里写着单轮 8.5~10.2 秒）——「干活请求」跳过投票，
   最近画像照给。`plan` 段从 **14.4 秒 → 0.23 秒**。

**还慢的地方（不粉饰）**：需要模型写句子的轮次仍取决于本机这颗 4B（「帮我写个快速排序」25 秒里
13.7 秒是模型本身）；而且当后台线程（逛世界/保养/自审）同时抢模型时，偶发一轮会翻倍 ——
`turn_lane` 能挡住大部分，但挡不住"模型自己慢"。这一段只能靠更快的火种或更狠的降级，
两者都是取舍，我不替你选。

## 六之六、行情类问题：从「37 秒 + 答错」到「5.6 秒 + 真数字」

用户截图那个问题（「帮我查一下今天美股三大指数的收盘情况」）暴露了两层毛病，都不是"模型慢"：

| 现象 | 根因 | 修法 | 实测 |
| --- | --- | --- | --- |
| 等了半分钟，最后答「我查不到，因为我调用 NVD 接口失败」 | 通用意图表里装着 `collect_vulnerabilities`，模型拿它去查**股价** | 把漏洞工具从通用 `query` 表里拿掉（漏洞问题本来就有专用规则路由） | — |
| 就算用检索，也搜不到点位 | `web_search` 回的是新浪/知乎**首页**，片段里没有收盘数字 | 新增 `plugins/market.py`：**载体直连行情接口**（东财 `push2` + 新浪 `hq.sinajs.cn` 兜底），一次请求出整张表 | 美股 **5.6 秒**、A股大盘 **5.7 秒**，零模型调用 |
| 「今天A股大盘怎么样」走了 37 秒 | 快路的否定判据里写了「怎么」，把「怎么样」也挡掉了；`大盘` 又不在关键词里 | 否定判据只挡**真诉求**（为什么/怎么办/分析/解释/生成…），并补上 大盘/沪指/两市/黄金/白银 | 同上，已归入快路 |
| 休市时显示「0.00%」 | 数据源给的是 0，其实表示"没更新" | 涨跌额也拿不到时，涨跌幅显示 **—** 并注明原因，不拿 0 冒充"没动" | 已改 |

**边界（如实说）**：行情接口是第三方公开接口，被限流/改字段时就查不到 —— 那就**如实说查不到**，
绝不编一个数字（行情编错的代价比不答大得多）；黄金/白银的 `secid` 各源不统一，目前仍会退回
"查不到"，我没把它写成"能查"。

## 八、边界（如实说）

- **账本防的是内部不一致，不是恶意篡改**：能读写这些文件的人也能重算整条链；
- **"有据"不等于"正确"**：它只说"这句话在这段材料里找得到"，材料本身对不对是另一回事；
- **闸门只能调参，不能改逻辑**：这是刻意的权限收缩 —— 想要新逻辑，得人写代码；
- **等价性是小样本实测**：6 条用例、每颗火种两次调用，数字看趋势；想更硬就得把用例扩到几十条并多轮跑；
- **长时项目不会自己找活干**：它只执行你交的目标；自动挑活的是 `core/auto_evolve.py`，而那一条只允许「缺能力」类真动手。
