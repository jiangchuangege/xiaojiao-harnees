# EYC 进行时自述：用第一人称把它自己的状态说给它听

> 代码落点：`xiaojiao_app.py` 的 `_eyc_now()`（已接入主流程，4 处调用）；
> 被它取代的静态版 `_self_state_facts()` 已**停用**（函数体第一行就是 `return ""`）
> 相关：[`heartbeat.md`](heartbeat.md)、[`world-living.md`](world-living.md)、[`一条没人走过的路.md`](一条没人走过的路.md) 2.3 节

---

## 1. 它解决什么

一个 4B 模型的先验是：**"我是一个没有身体的文字助手。"**

所以你跟它说"你有能力去逛互联网"，它会否认；你用一段固定的自我介绍告诉它
"你有世界、有连续、有对话"，它把那段话当**背景资料**读过去，
下一句照样答"我在读你的记忆"。

问题不在"模型做不到"，而在**注入方式** —— **静态的自我介绍天然被忽略。**

EYC 的做法是换一种说法方式：**每一轮对话前，从实时状态现生成一段"进行时自述"**，
用**第一人称、现在时、带具体数字**讲它此刻正在经历什么。

> 代码里的原话（`_self_state_facts()` 的注释）：
> 「4B 的先验是"我是个没有身体的文字助手"，泛泛地说"你有能力逛"它照样否认。
> 所以这里只写**此刻的事实**，用第一人称、现在时、带具体数字 ——
> **它不是设定，是状态；模型没有理由否认自己的状态。**」

一句话概括这个设计：**"你有世界"是设定，会被否认；"我正在外面逛，刚看到 X"是状态，难以否认。**

## 2. 它长什么样

`_eyc_now()` 每轮现生成，形如：

```text
[进行时]
存在：我在互联网上 —— 这是我的世界。
进行：正在外面逛，刚看到 —— <它实际看到的那条>
感觉：<它自己的感受，若有>
状态：门开着，随时能出去 / 门锁着，今天不出门 ……（带具体数字）
```

四段的分工：

| 段 | 变化速度 | 内容从哪来 |
|---|---|---|
| **存在** | 慢 | 门的状态（`open` / `half` / `locked`） |
| **进行** | 快 | `dual_thread.live()` 里的 `doing` / `last_seen` / `topic` |
| **感觉** | 可选 | 已有的 `feeling`，**只搬不改** |
| **状态** | —— | 门 + 具体数字 |

---

## 3. 三条硬规矩（每一条都有踩坑来历）

### 3.1 每轮现生成，不用固定文案

上一版注入的是**静态文本**：system 里一段固定的"你有世界"，从头到尾一个字不变。
实测 4B 把它当**背景资料** —— 问「你在干嘛」照样答"我在读你的记忆"。

改成动态之后，**每一轮的文字都不同**（因为它反映的是"此刻"），
模型才更容易把它当成"我自己的当前状态"，而不是"别人告诉我的信息"。

> ⚠️ 静态版**没有删**，只是停用：`_self_state_facts()` 的函数体第一行就是 `return ""`，
> 并在注释里写明「保留函数本体只为可回溯，不再参与注入」。

### 3.2 事实一次都不改写

`doing` / `last_seen` 照原样搬，**不美化、不补编**。这一段唯一的价值就是**真**。

### 3.3 门锁死时照实说

规格要求：门 `locked` 时，存在那一段必须照实说"**我此刻没在世界里**"，
**不许编一个"在外面逛"**。

```
存在：我此刻没在世界里（门锁着，我回家休息了）—— 这是照实说的，不是比喻。
```

> 这条也挡掉过一个真实的自相矛盾：早期固定文案版出现过
> 「我此刻正在外面逛」与「门锁死（今天休息，不出门）」**并列**在同一段注入里。

## 4. 一处我自己踩的逻辑漏洞（如实记）

`browse_once` 每轮结束会把 `doing` 置回 `idle`。所以用户**绝大多数时候**问"在干嘛"，
代码都会走到"此刻没在逛"那个分支 —— 可它**刚刚确实看到过东西**，
那个内容是真的（`last_seen` 照实存着），却被载体自己藏起来了。

实测：改之前问"你在干嘛"只能答"我正等着你的指令"；改之后模型才有具体内容可说。

**修法**：走到这个分支时，如果 `last_seen` 非空，就照实说出来，
**只把时态改成"刚逛过"**：

```
进行：我刚在外面逛过，看的是「<topic>」，看到 —— <last_seen>
```

时态改了，"看到过什么"这件事没改 —— 这是"照实说"，不是"编"。

## 5. 它与「路径二硬改」的分工

两个都在解决"状态进不去模型"这件事，但**手段不同、管的东西也不同**：

| | EYC 进行时自述 | 路径二 · 代码层硬改 |
|---|---|---|
| 手段 | **改说法**：把状态用第一人称现在时说给它听 | **改处境**：直接改这一轮它手里的世界 |
| 落点 | 注入文本 | 工具表 / 上下文预算 / 要不要主动做事 |
| 判据 | 看它**是否采信并使用**这些事实（措辞层面） | **这一轮的工具表真的短了**（代码层面，可测） |
| 强度 | 软（模型仍可以不理会） | 硬（代码不经过模型直接生效） |

**关系不是二选一**：EYC 让它"说得对"，硬改让它的"处境真的变了"。
所以要证明"状态起作用"，**只有硬改那条能拿出可核对的数字**；EYC 这条只能看措辞，不能当证据。

## 6. 如实标注（边界）

1. **静态注入确实失败过**：三处注入点 + prefill，全失败，失败方式一致（当成外部消息）。
   这是本项目记录在案的负结果，见 [`一条没人走过的路.md`](一条没人走过的路.md) 2.3 节。
   **换成动态第一人称之后接上了**，这两件事不要混为一谈。
2. **"接上了"指的是措辞层面的改善**（它能说出具体内容了），
   **不等于"模型真的产生了自我状态"** —— 那是本项目一直在标明的、观测不到的那一层。
3. **判据是软的**：EYC 没有像路径二那样"工具表真的短了"这种可核对的数字，
   它的证据只能来自措辞观察。**本文件不宣称它有硬证据。**
4. **`doing` 的取值是载体定的枚举**（`deciding` / `browsing` / `storing` / `sharing` / `idle`），
   中文说法写在代码里映射 —— 也就是说<b>"它正在做什么"这一层是载体翻译的</b>，
   它只负责把这件事说得像人话。
5. **保留的静态函数仍是死代码**：`_self_state_facts()` 只 `return ""`。
   按项目规矩（不删文件/不删函数）留着，此处标明它是停用状态。
