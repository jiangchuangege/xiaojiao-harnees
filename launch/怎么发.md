# 怎么发（手把手 · 照着做就行）

> 发帖的正文在 `launch/post-zh.md`（中文）和 `launch/post-en.md`（英文）。
> 这份文件讲**发之前的准备**和**每个站的具体点法**。

---

## 第 0 步 · 先准备 3 张图 + 1 段录屏（大概 40 分钟）

没有图，没有人点。这一小时花得比写帖还值。

### 图 1 · 封面
仓库里已经有了：`assets/xiaojiao_cover.jpg`。直接用。

### 图 2 · 最有说服力的一张 —— 原理图
在浏览器打开 GitHub 上这一页：
`https://github.com/jiangchuangege/xiaojiao-harness/blob/main/docs/architecture-diagrams.md`

往下滚到**最后一张图（图 20 · 载体改造·路径二四阶段）**，截图。
这张图上有「内感受 → 视角 → 硬改 → 归属回流」的完整闭环 —— **一眼就能看出这不是"套壳聊天"**。

### 图 3 · 证明"状态真的改了工具表"
截图终端里跑这个的输出：

```bash
python tools/test_state_policy.py
```

它会打印「精力 0.95 → 工具表长」「精力 0.10 → 工具表真的短了（6→0）」这类断言。
**这是整篇帖最硬的一张证据。**

### 录屏（用电脑自带录屏：Win + G）
录 30 秒，做三件事就够：
1. 跟它说一句话，看它回
2. 打 `/api/selfsleep` 或让它睡/醒，展示"它自己决定睡"
3. 让它抓一个网页

> 不用剪、不用配乐。**"没剪过的真实录屏"比精修视频更可信。**

## 第 1 步 · V2EX（推荐第一个发，反馈最快）

1. 打开 **https://www.v2ex.com/**，右上角注册（**需要用 GitHub 账号或手机号注册**，用 GitHub 最快）
2. 注册后**先别急着发** —— V2EX 对新人有限制，先去几个帖子回复一下（免得被当成广告号）
3. 点顶部 **「分享」** → 左边选节点 **「分享创造」**
4. 标题：粘贴 `launch/post-zh.md` 里第 1 个标题
5. 正文：**整篇粘贴**（Markdown 直接支持）
6. 主题配图：V2EX 正文里贴图片需要先传图床（**imgur.com** 或 **sm.ms**），传完把链接贴进来
7. 点发布

> ⚠️ V2EX 忌讳"标题党"和"求 star"。你的帖里**没写"求 star"**，这是对的 —— 保持那样。

## 第 2 步 · 掘金 / 知乎（第二个发）

**掘金**：https://juejin.cn/ → 注册/登录 → 右上角「写文章」→ 粘标题和正文 → **封面**选图 2 → 分类选「人工智能」→ 发布

**知乎**：https://www.zhihu.com/ → 登录 → 首页「写文章」→ 粘标题和正文 → 发布
（知乎对代码块支持一般，**图 2 和图 3 一定要贴**，不然读者看不到重点）

---

## 第 3 步 · Reddit r/LocalLLaMA（关键战场）

1. **先注册**：https://www.reddit.com/register （需要邮箱；**新号直接发帖可能被自动过滤** —— 建议先注册、隔一天再发）
2. 进 **https://www.reddit.com/r/LocalLLaMA/**
3. 看右边栏的 **Rules**，确认允许 "Show and tell / Project" 类帖子
4. 点 **「Create Post」** → 选 **Text** 类型
5. Title：粘 `launch/post-en.md` 里的第 1 个标题
6. Body：整篇粘贴（Reddit 支持 Markdown）
7. **Flair：一定要选**（比如 `Discussion` 或 `Project`）—— 不选会被删
8. Post

> ⚠️ Reddit 新号第一帖常常被自动隐藏。**如果发完 10 分钟没有任何浏览，就是被过滤了** —— 去 modmail 礼貌问一下，或换 r/LLMDevs、r/selfhosted 发。

---

## 第 4 步 · Hacker News（Show HN）

1. https://news.ycombinator.com/ → 右上角 **login** → **create account**（只要用户名+密码，最简单）
2. 点顶部 **submit**
3. **title**：`Show HN: XiaoJiao – carrier-first local AI assistant; swapping the model changes nothing`
4. **url**：填仓库地址 `https://github.com/jiangchuangege/xiaojiao-harness`
5. 提交后，**立刻在下面发第一条评论**：把 `launch/post-en.md` 的正文贴进去
   （HN 的规矩就是这样：链接帖 + 作者自述放评论）
6. 前 2 小时最关键 —— **有人评论就尽快回**，哪怕只说"你说得对，这点我没考虑到"

> ⚠️ HN 账号**没有 karma 限制**，但**同一时间只能发一条**，别连发。

---

## 第 5 步 · 发完之后（决定了能不能滚起来）

1. **2 小时内盯着回评论**。技术社区最看重"作者在不在场"。
2. 遇到这两类质疑，你有现成答案：
   - **"这不就是 XX 项目吗"** → "XX 是把能力放在模型侧/提示词侧；我做的是**代码层硬改**，判据是'这一轮工具表真的短了'，而且我写了**注入四处全失败的负结果**"
   - **"4B 就是不行"** → "对，单次推理不行 —— 我这份帖讲的就是**哪些能靠架构补、哪些补不回来**。元认知那跳我就明写了没通"
3. **别改帖**。发了就发了，要补就在评论里补。
4. 发完 24 小时看看数字，**不满意就换标题重发到另一个站**（同一个帖换站重发是正常的）。

## 关于"小焦比前沿模型差远了"这件事

**这是真的，而且不用藏。** 它连"这数对不对"都会答错。

但你发帖要讲的**不是"我的 AI 比 GPT 强"**（那必输），而是这个没人有答案的问题：

> **一个本地小模型，靠载体架构能把差距补到什么程度？哪些补得回来，哪些补不回来？**

你手上有别人没有的东西：**注入四处全失败的记录、工具表 6→0 的判据、元认知那跳没通的实测**。
**在这个问题上，你不是弱者，你是少数有实测数据的人。** 按这个定位发，就不会被"你这也叫 AI"打回来。
